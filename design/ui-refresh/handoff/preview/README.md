# 独立设计模拟状态

此目录仅为下一阶段 Figma Make 原型的状态契约。它不是当前 Electron 实机截图，不运行生产业务，不证明任何新任务生成、采用、恢复或下载成功。

`design-states.json` 用引用连接 `../upload/03_SAMPLE_CONTENT.json` 的真实内容 ID。内容原文与正式采用关系只读；`presentation` 是独立界面模拟。禁止把模拟的 pending、error 或 candidate 写回项目、任务、Store、IPC 或原始素材。

三种预览分别是：

1. 生成中：在代表镜头上演示阶段反馈，无平台百分比、倒计时和自动成功。
2. 真实错误／提交受理不明：优先引用样板内存在的错误原话；提交未明子态若缺现成实例，明确为依据已有恢复合同派生的「设计模拟」，不假称截图证据。
3. 候选待采用：引用现存可读资产演示选择与采用的界面。样板 `a76a5de5-1eaf-4176-9259-a5b610cb7e31` 的历史字段虽为 candidate，已被当前首帧的 `resolvedCandidateIds` 收束，**不是当前待处理候选**。本地可用该历史未采用图投影“待采用”；首批上传不含这张图时，只能用已附 `08_KEYFRAME.png` 演示其界面并标为“已采用图片的设计投影”，不能假称它实际待采用或制造一张不同结果图。

所有视图须有持续可见的「设计模拟」标记。点击模拟动作只更新原型内存，可展示交互后返回，不可调用 `window.electronAPI`、本机控制接口、豆包页面或网络生成 API；不可添加定时“生成成功”脚本。

真实服务入口、尚未自动实现的步骤以及原型与生产差距见 `../upload/02_INTERACTION_MAP.md`。模拟不得掩盖：方案后台反馈未接通、重复定位入口、跨任务的成果质量确认、旧诊断／更多／待处理入口，以及视频重新生成的现有入口限制。

本目录无需上传到 Make 的首批 10 文件中；若第二阶段需要补状态，可以把本契约的相关片段贴入第二份指令。`upload/` 是可移植内容材料，`evidence/` 是本轮事实与本地走查材料，二者不被本目录模拟覆盖。
