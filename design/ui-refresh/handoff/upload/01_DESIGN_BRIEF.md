# 短剧工作室 · Figma Make 设计简报

日期：2026-11-02。交接阶段：真实产品整理 → **一套可交互视觉原型** → 用户新的明确批准 → 后续实现。本轮没有批准新 UI，也不修改正式产品。

## 产品与本轮任务

产品名「短剧工作室」，主界面「创作工作台」，业务名「短剧创作」。面向以剧本、角色、镜头和成片素材组织创作的人，做专业、精致、以作品为中心的桌面软件。1699 元只说明产品定位，界面不出现价格、购买、订阅或宣传模块。

本轮 Product Design 提供操作取舍和布局依据；Browser／Electron 提供当前事实；Figma Make 下一阶段据此完成同一套原型。本简报不另造一套竞争视觉，不要求照抄截图中的旧按钮与视觉。旧设计批准仅说明历史版本曾获批准，不能恢复已撤销入口。

## 不可改变的画布骨架

保留现有 ai_story 式空间画布：**左侧故事与基础素材，右侧每镜一行，横向依次为分镜／图片提示词 → 关键帧 → 视频提示词／运镜 → 视频。** 首帧与必要尾帧属于对应镜头，不另拆成全局表单。网格、空白处拖动平移、缩放、定位及固定镜头导航均保留；导航列出样板项目的全部真实镜头，不写死五镜或六镜。

以 `03_SAMPLE_CONTENT.json` 的真实项目、全部镜头顺序及代表镜头为内容依据。样板须让长正文、图像、视频、采用关系与候选并存。屏内可摘要，摘要是另一个字段；完整代表性提示词必须可读，不把它替换为一句排版用假内容。

## 正常创作流程与决定权

输入剧本 → 确认方案 → 准备基础素材 → 关键帧 → 镜头视频 → 成果。

| 环节 | 原型应表达的交互 |
| --- | --- |
| 剧本与方案 | 输入／查看原剧本，查看角色和实际分镜，明确确认方案；修改方案保留用户决定。不得假装尚未接通的后台方案反馈已可用。 |
| 基础素材 | 点击「生成图片」后由软件准备必要文字并生图；用户只预览、反馈、采用。上传也先候选预览再采用；不恢复基础提示词编辑／采用步骤。 |
| 画布提示词 | 一个清楚的生成入口 → 对应目标真实进度 → 完整候选回到原节点 → 确认使用或自然语言修改。格式修订、回读、保存由后台完成。 |
| 图片预览 | 明确指出正在看的具体图片及用途，区分当前采用、待采用和历史。反馈绑定选中的图片；可修改上传、未采用和历史图，支持连续反馈。未采用前正式图保持。 |
| 镜头视频 | 用户明确生成视频；呈现当前使用的首帧／首尾帧／参考图和真实时长。视频文字安排动作、表演、逐字对白、声音与运镜。 |
| 成果 | 显示真实可读的镜头素材、播放与保存结果。技术任务结束不等于用户确认质量，不展示未实现的合成完成。 |

新项目角色为空，从剧本提取；不默认噜噜、噜妹、物种或特定美术。样板中出现的旧项目名字是该项目内容，不是新项目默认。**明确采用的角色图决定当前形象**；旧文字可追溯，不能重新覆盖图片。换图保留历史媒体，只影响使用该角色的镜头和实际连续依赖，不自动重做全项目。

豆包默认在后台运行。工作室内完成普通确认、反馈和采用；仅主动进入对应真实会话，或真正需要登录／人机验证时提示处理。不能设计成用户在工作室与豆包来回读取、复制、确认的常规流程。

## 同一套视觉方向

方向是「作品桌面」：延续当前真实产品的浅灰工作区、白色内容节点和克制青绿强调，将精力用于层次、排版、媒体比例和动作优先级。不要在本轮另做深色、渐变或宣传式方案。此方向是下一阶段设计输入，仍须新原型获得批准。

`DESIGN.md` 仍记录早期“豆包工作室／深色紫色／账号任务三栏”；它与当前 `src/styles/global.css`、`storyboard-canvas.css` 及本轮命名、画布要求不一致。不能据该旧文件把产品改回任务控制台。

1. **外壳让位于作品。** 项目名只出现一次；主导航负责项目、创作、账号、设置等真实目的。账号与内部任务不是画布常驻主角；不要新增首页统计、待办或大段说明占据创作区。
2. **节点先给内容，再给动作。** 标题层呈现镜头号、用途及必要时长；正文层呈现剧情、提示词或媒体；底部只放当前可做的创作动作。动作颜色用于「确认使用／采用／生成」等当前主决策。不能让每个内部服务都变成按钮。
3. **文字可扫读，也能完整阅读。** 节点给真实正文的有边界预览与一个「全文」入口；全文内可反馈。专业手动编辑若保留，只在对应全文按需进入，避免与自然语言「修改要求」并列争夺注意。两者语义不同，不应把技术编辑当成必经步骤。
4. **媒体占据视觉中心。** 图片按原比例完整预览；缩略图只辅助选择，选中状态不能只靠颜色。视频原位播放或进入唯一预览，避免重复播放入口和相同说明。采用关系与候选关系清楚，不能用漂亮素材掩盖缺图或失败。
5. **一处讲清一件事。** 节点内真实状态为主要反馈；工具栏只保留批次整体进度。正文来源、字数、状态、错误原因不在多个区域重复。登录、文件错误和提交未明需可见，不以折叠详情隐藏。
6. **画布工具只做空间控制。** 当前百分比按钮、「适应」和「定位镜头」都调用同一 `focus(activeShot)`。原型合并为一个清楚的当前镜头定位／恢复可读视角动作，加缩小、只读比例、放大；保留逐镜导航，不虚构三种不同模式。

## 必须消失与不得扩展

不恢复通用创作、免费确认、人工入口检查、待处理事项面板、诊断详情、生成记录、基础素材提示词编辑／采用、局部编辑计划、常驻「更多」或省略号替代菜单。不是把所有入口移到「高级」「工具箱」「详情」或换名字继续保留。

日志与必要恢复可在内部工作；确有独立用户价值的高级内容编辑只在具体全文按需提供。未自动实现的步骤不能直接藏掉造成死路，须按 `02_INTERACTION_MAP.md` 的实现差距保留准确交接说明。

不扩展 P5 合成、配音、字幕、自动发布，不新增模型 API，不新增后台系统。Dola 尚无真实端到端人工验收，不能设计为生产可用。也不把下载按钮隐藏作为“已经自动下载”的证据：只有当前链真实完成下载与校验，才可呈现已保存。

## 状态、异常与可交互要求

原型至少覆盖：无内容／可开始、生成中、保存中、候选待确认、已采用、自然语言修改中、历史内容、失败、登录／验证、提交受理不明、文件不可读。状态必须绑定具体镜头、提示词或素材，不能一个全局成功标签覆盖全部节点。

生成中仅显示真实可观察阶段，不编造平台百分比和倒计时。候选完成不自动采用。可修复格式问题在后台修订；用户仍决定内容变化。实际失败保留简短原因及唯一直接动作。

提交受理不明先保留「检查原结果」；用户明确「确认重发一次」才走既有关联任务授权链，先处理原账号登录／验证，同一原运行不循环重发。不能以通用「重试」静默发送。细节见交互映射。

独立 `preview/` 只包含标为「设计模拟」的状态数据契约，不是实机截图，不连接 Electron IPC，不证明平台生成已完成；`upload/` 中真实数据不被模拟状态改写。

## 两个必须交付的桌面尺寸

以 **内容视口 1440×900、1280×800 CSS px** 设计并回归；截图 DPR 与实际画布缩放见本地证据记录，不从 PNG 像素数猜测。原型演示时也注明自身 DPR 与缩放，两类数据不能混写。

- 两尺寸都保留相同空间骨架，不因窗口缩小改为表单／纵向列表。全部真实镜头可定位；导航固定在画布视口，随节点缩放的只有内容层。
- 收起辅助浏览器后，网格至少占创作区内容高度的 75%；不需页面外层滚动才能接触画布。缩放及更新进度不重置视角。
- 1280 下可压缩外壳／次要标签，不能靠把正文、按钮缩得难读来容纳。保留平移和全文阅读；长文本、图片选择与反馈输入在各自区域滚动，操作按钮可达。
- 全文、图片预览、反馈一次只打开一个主弹层，标题和主操作始终在视口内；关闭后保留原镜头、缩放与平移位置。键盘焦点可见，按钮有可理解名称，错误不能只靠颜色表达。截图不能证明完整无障碍达标，后续实现仍需键盘检验。

## Figma Make 验收边界

下一阶段用随包素材做**同一套**可交互原型：完整真实镜头导航、代表镜头全细节、全文与自然语言反馈、图片候选与采用、视频预览、真实异常处理、账号与设置的必要入口，以及两尺寸布局。原型内使用模拟状态须持续显著标为「设计模拟」，不把按钮动画当成现有服务接通。

当前截图用于保留布局和验证内容复杂度，当前生产能力与原型目标见 `02_INTERACTION_MAP.md`；本轮没有新增豆包文字、图片或视频任务。原型完成后先由用户明确批准，之后 Codex 才实施正式 UI，并按真实服务补齐接线、回归状态与异常。
