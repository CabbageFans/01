# 短剧工作室 · 交互与操作取舍

本文件供 Figma Make 制作同一套可交互原型。现有入口与真实调用来自当前工作树；“最终去向”是本轮设计要求，尚未实施或批准。详细源码行号留在本地 `evidence/source-map.md`，不用把仓库上传 Make。

## 六阶段与固定画布

| 阶段 | 用户决定 | 结果与下一步 |
| --- | --- | --- |
| 输入剧本 | 输入、修改完整原文；点击分析 | 先保存原文，后台分析；方案回到确认阶段 |
| 确认方案 | 查看完整方案、提出内容修改、确认采用 | 明确采用后才成为制作依据；准备人物、道具、场景 |
| 准备基础素材 | 生成或上传→预览→图片反馈或采用 | 必要文字后台准备；图片先候选，采用图才决定当前形象 |
| 关键帧 | 生成/确认镜头提示词；生成或上传首帧/可选尾帧；反馈、采用图片 | 文字与图片各自候选确认，采用文字不自动生成图片 |
| 镜头视频 | 确认视频正文、时长等具体设置；点击生成视频 | 用当前采用首尾图与完整正文；真实平台异常在视频节点恢复 |
| 成果 | 看实际画面与声音、播放、打开成果、作质量决定 | 保留逐镜素材及历史；文件保存不等于内容质量合格；不扩展合成、配音、字幕、发布 |

关键帧、镜头视频与全景继续共用 ai_story 式画布：左侧故事与素材；右侧每镜一行；横向为分镜/图片提示词、关键帧、视频提示词/运镜、视频。保留网格、平移、缩放、定位及全部实际镜头导航。代表镜头展示完整细节，其他镜头仍可定位；不能把画布换成表单或列表。

**已取消入口不再出现。** 通用创作、免费确认、人工入口检查、待处理事项面板、生成记录/诊断详情、更多/省略号菜单不得换名回归。日志仍可内部保存，具体异常恢复回到所属方案、图片、文字或视频；不能把全部内部能力迁入一个“高级”菜单。账号管理及设置保留与用户目标相关的具体内容，不把自动检测、技术记录变成创作必经步骤。

“手动修改”与“修改要求”目前并排，认知重复但调用不同：直接保存正式正文与 AI 生成新候选必须分清。正文、错误说明、状态标签以及多区域任务状态要去重。正常创作留在工作室，只有主动自由交流、真实参数确认、登录验证、会话归属缺失才需要到豆包。

## 状态与转移

下面是原型必须覆盖的交互合同。没有本轮真实截图的状态只能放独立 `preview/` 并标“设计模拟”；不能改真实数据凑状态，也不能为演示新发任务。

| 状态 | 呈现与可用动作 | 转移与保护 |
| --- | --- | --- |
| 无内容 | 剧本输入/真实空素材/空镜头节点；保留对应生成或上传 | 输入→分析；方案未确认时先方案决策。不要另加技术资格提醒卡 |
| 生成中 | 所属节点显示真实阶段/动态进度，允许浏览其他内容 | 已授权任务自动推进；不编造百分比、倒计时；禁重复提交 |
| 保存中 | 显示正在读取/保存当前结果 | 只有合法全文/可读文件实际保存后才进入候选；失败保留原任务及旧成果 |
| 候选待确认 | 完整文字或图片预览；确认使用/采用、提出修改、暂不采用 | 采用只改变对应对象；关闭不采用；收到候选不覆盖正式内容 |
| 已采用 | 当前使用的正文/图片清楚标识；可看全文或提出修改 | 修改形成新候选；采用图决定形象；不自动生下游媒体 |
| 反馈输入/提交中 | 固定具体节点、版本或基图，单一自然语言输入 | 空意见/取消零请求；提交中防重；成功回所属节点，失败保留意见 |
| 历史/被替换 | 标清旧版本，保留完整正文、图片与视频查看 | 不能冒充当前制作依据；可明确选历史图作为反馈基图；不自动夺回当前采用 |
| 失败/平台拒绝 | 原位给真实、简短原因及实际可用恢复 | 先区分未发/已发/文件失败；不泛化成重生，不隐藏失败 |
| 登录/验证 | 原对象提示进入原账号处理；返回后检查/继续 | 本次 fresh ready 才续唯一原任务；已提交只读收取；用户暂停/取消不算授权 |
| 提交未明 | 保留原请求、输入、迟到产物；检查原结果入口 | 默认只读核对；用户明确风险确认才单次关联重发，禁止循环 |
| 平台参数待确认 | 展示原模型/时长/比例及去原会话/检查结果 | 用户在平台确认后沿原运行只读检查；不能假称工作室自动代确认 |
| 文件读取/下载/解码错 | 局部错误；保留文件与来源，提供真实可用恢复 | 仅补原下载/重新读取；不能把无可读文件标成功或新发生成 |
| 保存冲突/未保存草稿 | 保留输入，显示保存失败/版本变化与保存、放弃 | 导航不丢内容；后台回填不覆写编辑框；恢复后再生成 |

## 七项实现差距与接通方式

这些是设计与当前能力的差距。原型可以展示目标体验，但应在交互说明标“待接通”，实现时先接通既有服务，再移除唯一必要入口。

1. **方案后台自然语言反馈。** 目前是 `openChatAdjustment` 的豆包自由交流、具体回复选择和预览采用。目标可在方案全文内反馈；须复用 Chat runtime 校验/候选服务，绑定父方案、当前版本与基准。后台方案反馈完成前保留真实会话调整路径；自由交流不能自动选回复。
2. **删除面板后的原位恢复。** `PlanRecovery`、`PetStoryChatRecoveryActions`、`PetStoryCurrentTasks` 已有保存回复/检查原回复/结束等待能力。移除常驻待处理及诊断后，按最新关联 job 在方案本体接回相同 handler；不让异常变无入口，也不要求用户去内部任务记录猜操作。
3. **全编辑对象自动保存。** 原文分析前保存与任务结果后台保存已存在；方案、手改正文、视频设置仍需明确保存。复用 `savePlan`/`saveShotPrompt`，补去抖、revision 冲突、失败重试与导航保护后才能使用“自动保存”承诺；此前保留真正保存动作。采用始终独立。
4. **成果就地质量确认。** 当前成果按钮跳任务中心。若目标在成果直接确认，复用 `useTaskStore.setQualityVerdict`/既有任务质量服务，准确绑定 task/run/asset；不能把下载或解码自动判为质量合格。
5. **诊断和更多删除后的能力归位。** 目前方案/项目/任务/设置仍有这些入口。内部日志继续保存；实际错误在具体对象解释，独立创作编辑放具体内容全文内。账号的改名/管理保留在具体账号内容；不得用“专业/高级工具”重新造更多菜单，也不能移走必要恢复后不接服务。
6. **已有视频的再生成。** 当前有视频资产时节点只显示查看视频，未暴露重新生成按钮。若目标在视频全文内按需提供重生，接 `generateShotMedia`，明确新一次创作决定、保留旧成片、检查原任务防重；不能写成现有 UI 已支持。
7. **真实平台全链与状态证据。** 最新角色报告的代表视频文字在提交前页面/上传识别阶段失败，没有新媒体生产。原型进度/成功状态不证明服务已验收；实现仍用正式 Chat/ImageOperation/Production/TaskService 链补真实验证。Dola 端到端未验证；不加模型 API 或另建后台系统。

## 本轮取证边界

真实原项目样板为 **6 镜**；当前桌面打开的 `ui-project` 为此前验收派生的 **5 镜副本**，两份来源不能混写。便携数据和样板导航以 `03_SAMPLE_CONTENT.json` 标明的 6 镜真实原项目为准，不固定套用桌面副本数量。

本轮隔离 `mac-test` 运行当前原组件、真实 Electron 与真实 IPC，并使用项目副本；**没有复制账号、任务或 Session**。因此该环境出现“原任务归属不符”等提示属于取证环境缺少原关联，不能称为原项目真实生成失败，也不能跳过正式校验使其显示成功。截图是当前组件在该隔离条件下的实机证据，不是用户原账号生成全链验收。

本轮没有发起新的豆包文字、图片或视频任务。已有视频及海报是项目中真实保留媒体，只证明该文件存在可展示；不证明其对应当前正文、当前角色图或当前参数，也不证明新规则生成效果。生成中/失败等派生演示若无实机证据，必须独立标“设计模拟”。
