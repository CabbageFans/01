# 基础素材先行：实现与使用

本文使用流程已按 2026-10-30 产品规则更新：不再要求免费声明、人工入口检查或素材引用免责声明；原实现和验收记录保留。复用 P1～P4 及现有短剧 UI，不实施 P5。

## 使用流程

1. 运行 `pnpm run dev:mac`，在原豆包账号创建／打开短剧项目。可直接保存剧本，也可保留抖音链接与手机故事回填流程。
2. 点击分析；检查故事、动态人物／道具／场景及草稿分镜。人物名称与描述可编辑，道具保留别名、关键状态和比例，场景区分主图与同地点派生视角。保存后在“基础素材与制作准备”确认剧本和清单；此操作不生成媒体。
3. 单独点击缺失基础图生成／某项重生成，或上传已有图片。派生视角需先接受主场景图片，再继续原基础图制作；图片成功下载仍是待接受。
4. 点击具体图片可放大；可检查其实际生成时提示词，修改后保存当前基础图提示词、重新生成或选择旧图。接受单图，或勾选已检查的图片后批量接受。替换图片会清除该图确认；旧文件、生成任务与历史成果保留。替换主场景还会清除派生图确认。
5. 全部必要图片接受后，查看镜头数量和实际模式，再点击“确认素材，继续镜头制作”。镜头可见人物 ID、关键道具／持有者、场景 ID 与视角、起止动作／神态／视线／互动／台词及镜头方式。修改未保存时禁止启动。
6. 首帧组合仅上传本镜必要确认图；尾帧编辑使用所选首帧。视频首帧只用首槽，首尾用两个专用槽，多参考使用当前镜头首帧及相关确认图。附件超限或映射不明会暂停，须调整计划／使用用户确认的组合图，不自动漏掉素材。
7. 执行器在开始任务后读取当前入口。支持 @ 时通过当前菜单选素材并回读真实节点；确实不支持时，只使用已有且确实可执行的中文用途映射适配，不要求用户额外勾选。控件无法识别不能当作“不支持”，入口不存在或映射无法核实时报告具体原因。完成后在原任务详情和项目逐镜素材查看下载成果。

## 提示词审阅与正式导出

点击原短剧页“导出提示词与引用记录（不生成媒体）”，选择已有保存目录，默认定位当前项目，并通过“导出到此文件夹”确认。每次创建独立目录，包含 `review.html`、`model-prompts.txt`、`prompts.json`，不改写项目与先前导出。先保存当前编辑；有未保存修改时不允许导出。

- `final` 保留用户正文；`modelPrompt` 使用与生产相同的编译器，附加当前用途和引用用途。计划素材未就绪只输出计划，不能冒称上传完成；`auto` 尚未解析时视频模型正文为空并报告原因。
- `referencePlan` 是逻辑资产与计划顺序。`review` 保存来源、状态、旧动作字段和审阅提醒，不参与模型提示词。
- `actualRuns` 保存已经存在的实际文件摘要、原生引用节点／素材目标或首尾槽、任务和运行 ID。分别标记绑定未发送、提交意图不明、平台受理以及证据不足；没有真实运行时为空，不生成模拟“已发送”结果。
- 人物确认同时接受当前规范外观文字与具体图片；更换任一项需重新接受。角色剧情作用与其他人的动作不进入人物身份提示词。旧通用风格保留在设置内，分别整理到共同画面语言／人物／道具／场景字段后再使用。
- 首帧只使用开始状态上下文，尾帧使用目标终态，视频使用动作过程与已有对白。final 不被旧动作字段再次拼接，也不由导出过程自动润色。

普通 Chat 未读回时，在任务详情点击原会话只读核对。旧任务没有保存原会话地址时，先在原账号切到相应对话，再点击“核对当前 Chat 原回复（不重新发送）”；只有唯一用户消息与原提示词全文匹配，才绑定会话并保存原回复。回读保留平台原文，结构不合格则走原正式格式校验，不把人工审阅稿当结果。

## 数据与保护

- 继续使用 `project.json`，新增 `plan.props/scenes`、镜头显式关系、`storyApproval` 和 `materials`。逻辑材料 ID 与具体 `assets[].id` 分开；审批绑定图片 ID、SHA-256 与角色规范外观文字。新基础图存 `materials/`，原 `characters/`、`shots/` 文件保留。
- 基础图与镜头共用原 ProductionService 的 hold、运行绑定、提交保护、观察、下载和媒体校验，但有独立 phase 和明确授权。历史制作快照保存在项目内；打开项目不会自动启用推进。
- `original/optimized/final` 沿用原语义。final 是正文；编译补入当前用途与模式，再按真实网页映射解析编号。手改 final 不被改写；网页解析后的全文同时保存在步骤编译快照与 TaskService 当前运行输入。
- 页面逐图上传，检查新增预览与原预览稳定对应，再解析实际编号。记录保存逻辑资产 ID、顺序、用途／槽位、上传文件摘要、不透明预览摘要、素材目标和每次节点 ID，不保存预览 URL。发送意图前再次回读预览、引用节点、模式和全文。
- 文件变化、素材未确认、页面不稳定、受理不明仍按实际问题处理；免费未知或缺少本会话检查记录不阻断。下载失败仅重新下载原产物，已受理观察原会话。连续动作提取前镜实际末帧，并在新首帧中重新组合项目确认标准；不把计划尾图冒充实际末帧。
- 旧项目可读且不自动改写或假定批准。旧方案没有道具／地点集合时，在原业务页补齐并保存后再确认。历史任务和成果保留；旧独立草稿入口只回显正式制作中已绑定的任务，不新增可绕过门禁的媒体草稿。
- 完成后的素材替换保留已有成果，不自动重做视频或合成。再次生成仍需明确操作；完整短剧合成及完整局部重做不在本轮。

## 验证与人工验收边界

离线验收使用音乐学徒、空间站检修以及新增的图书馆地图册交接、无人温室设备启动等无关小剧本，覆盖不同人物／镜头数量、同地切镜、真正跨场景、道具换手、设计待确认、图片版本与摘要审批、缺图生成／已有图复用、派生视角依赖、final 持久化、实际任务输入与附件、三种模式、网页重排与原生引用菜单节点、丢图／错节点阻断、下载重试及普通 Studio 隔离。旧 P4 回归继续覆盖下载解码、实际末帧、暂停恢复与受理未知。

实际图片质量、角色／道具／空间一致性、当前账号网页的 @ 菜单与真实原生首尾槽、视频表演与台词效果、附件上限仍需真实媒体验收；不要求用户先证明免费或独立检查入口。离线模拟只证明程序规则和组装；不记为真实平台／视觉通过，不承诺一次成功。Dola 仍未完成端到端人工验收。

最终门禁和 OpenSpec 状态记录在 `PETSTORY_PROGRESS.md` 最新一节与本变更 `tasks.md`。
