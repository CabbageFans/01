## 已查明的链路问题

核查业务入口 `CanvasPromptEditor → usePetStoryStore.optimize → petstory.prepareRuntime → buildDramaRequest → TaskService hold → 原账号 BrowserPanel → chatReadback → collect → candidate/final → compilePrompt/export`。原项目及原始记录已备份在不入库的 `artifacts/chat-internalization/`。

1. **实质规则确实进入旧请求。** 原第 2 镜首帧、尾帧、视频的真实 TaskService 输入含对应工艺规则，不能归因为“只加载标题”。旧三项原回复与正式任务回读、解析 optimized、保存 final 逐字相同，未发现该处丢失或固定截断。
2. **目标方言未进入旧视频请求。** 原项目没有 `promptCapability`，旧视频规则选择只得到通用 `video`，没有 `video20/video25`；不能把未知版本说成专用方言合规。
3. **原请求主动禁止了本轮需要的引用。** 全局约束禁止“固定图片N编号、裸@”，只带 Chat 附件表，没有目标媒体生成标签表。旧原回复无 @ 是请求契约问题，不能归咎解析。
4. **尾帧任务不够具体。** 旧尾帧原回复是独立画面描述；虽带尾帧工艺规则，但抽查请求仅附人物图，缺选定首帧文字与明确的编辑基准任务。编译器再加“编辑首帧／保持……”把这部分工作替模型补完。
5. **编译器追加创作说明。** 首帧、尾帧、视频和基础素材模型正文曾包含固定用途句与逐图身份／道具／场景说明，导致导出／提交全文不同于原回复；现已移除，只转换正文已有合法引用。
6. **保存与修订边界。** 原采用前未检查全部引用／方言，结构正确但错误编号可能先采用；批量修订未转移队列 jobId。现保存完整无效候选和具体原因，原请求／原回复一并反馈，最多一次完整修订，队列跟随修订任务。
7. **真实试发发现普通 Chat 技能残留。** 检查模型后页面处于视频技能；普通 Chat 空根页复用未退出技能，开始把 Chat 附件上传到视频输入框。本轮原任务在提交前由正式控制接口暂停，正文未发、媒体请求为零。新增普通 Chat 门禁：根页复用先排除草稿／旧附件，只退出明确媒体技能，上传前和提交意图前再次只读回验；未知状态即暂停。修复后原 taskId 恢复为第 2 次未提交重试，只实际发送一次，并正常取得原回复。

8. **一次真实修订的显示回读差异。** 第 2 镜视频修订已单次发送，但豆包显示层消耗 JSON 内两处引号前的转义反斜杠，完整请求比对未通过而暂停。限定在有 renderedSource DOM 证据、没有代码区／反引号的分支处理合法引号转义显示，仍比较全部正文；不泛化空白／前缀匹配。沿同一原会话只读恢复原 task，未重发、未代写回复。
9. **嵌套请求的 Markdown 空白变化没有安全放行。** 第 1 镜视频唯一 repair 虽有单次用户消息和原助手回复，但嵌套 JSON 显示仍有 401 处空白差异，缺少证据证明都可忽略，正式任务保持 submission_uncertain。后续结构化事实和原请求／原回复置于动态 JSON 围栏，返回约定也优先 JSON 代码块；PRE/CODE 内容先逐字核对，只有围栏外壳长度允许规范化，代码内空白和转义不改。旧修订没有重发。
10. **待核对文字任务原先锁死全部后续文字。** 正式暂停且已提交的 submission_uncertain 原任务保留全部绑定，仅在项目／账号／run／输入及附件均对应、无可收取回复时，允许继续不同镜头或不同素材的明确文字目标。同镜头首尾／视频、全局任务、活动／未提交／归属不明任务仍阻断；媒体入口仍因未收 Chat 暂停，不把继续文字当成原任务成功。
11. **新素材仍存在程序正文直通生产的路径。** `syncMaterials` 曾将程序拼接的设计稿同时写入 original／optimized／final，正常生图与模型导出可直接采用。现仅保留 original 预览，新 draft 的 optimized／final 为空；统一编译与制作前要求已保存采用的普通 Chat 材料正文或用户明确手改。旧无来源正文不擦除，缺来源时阻断模型输出并说明原因。当前原项目七项已有材料 Chat 来源，不需要重生成。
12. **内容审查错误原先只留在 job。** 单项审查若精确对应当前非手改 final、没有不同的未采用候选且上下文未变，明确 error 现会同步 needsReview 和导出警示／证据。手改、候选混合、过期和全局审查不作无证据归因；不据此自动补稿或再发修订。

普通段落 JSON 的网页显示可给用户消息中的 `@图片N` 插入空格；没有原始 payload 证据时，不能把所有可见空白都归咎模型。代码块原回复可以逐字保留紧凑标签，本轮后续任务已强制合法 JSON 代码块；对早期普通段落只如实报告正式回读版本及未确认的显示影响，不擅自去空格“修好”正文。

## 当前实际任务模板与规则映射

模板由 `main/utils/petstoryRuntimeRequest.ts` 的 `taskBrief`、`referenceWritingPolicy`、`targetGeneration`、`targetReferenceFacts`、`sharedShotState`、`sharedFrameFacts`、`previousAdoptedBoundary` 和 `outputContract` 直接构成；实际完整请求保存在正式 task/runtime 与 job.requestText，没有另写一份与运行脱节的样稿。

| 产品任务 | 实际规则阶段 | 对话职责 |
| --- | --- | --- |
| 剧本理解／共同镜头设计 | analysis + assets + storyboard | 原文与已采用故事、因果、原台词、资产身份和全场空间；新拆镜候选与保留原镜的资产补齐分开 |
| 人物基础图 | imageCharacter（显式编辑才加 imageEdit） | 单人物稳定身份、比例、衣饰及可复用画面；不带后续剧情 |
| 道具基础图 | imageProp（显式编辑才加 imageEdit） | 单道具结构、材质、尺度与单一外观状态；不带持有人和剧情流程 |
| 场景基础图 | imageScene（显式编辑才加 imageEdit） | 地理边界、通路、布局、固定锚点和光源；默认无人 |
| 静态首帧 | firstFrame + Seedream 适配 | 只以起点为正向画面，具体机位、人物方位、手物关系与表情；终态另列仅防提前检查 |
| 尾帧编辑 | lastFrame + Seedream 适配 | 原回复自己写编辑对象、目标改变、静态终态与具体保持集；已采用首帧文字与图片状态明确 |
| 视频 | video + 当前实际 video20 或 video25 | 正确目标模式、共同起终与已采用首尾文字、触发／过程／反应／落点、逐字台词；当前未知模型只用 generic |
| 审查／一次修订 | review 或原创作阶段＋所选问题 | 具体证据与影响；修订带完整原请求、原回复及缺项，不由程序或开发者改稿 |

规则资源只调整宿主适配版本为 `drama-skills-0.9.2-studio.2`，保留实际已有上游来源与许可，不为匹配旧说明升级或回退。

本轮按实测逐步修正模板和读取器。早期第2镜及第1镜请求还未使用结构化事实围栏；第3镜开始保护事实代码块，随后将返回代码块从“优先”改为“必须”。这些变化只用于之后的新请求，已发送任务及其原回复没有倒改。每个实际版本以 job.requestText 和正式 runtime.input 为准，不能拿最终模板冒充本轮所有历史输入。

每次请求区分任务、模型／模式／时长／画幅、实质规则、确认事实、共同状态、参考清单、返回契约和本任务自检。`attachmentList` 仅说明 Chat 看图；`targetReferenceList` 列媒体稳定身份、标签、用途、计划／可用状态及独立 chatImage 对照。未选用的历史帧只作分析，不能冒充新目标基图。

已知 Seedance 方言要求模型在相关句中自行写 `@图片N`、原台词声音块 `{角色用中文说：“原句”}`、所有选用声音（含环境底声）的单对 `<具体声音内容>`（禁止 XML 成对标签）、无内部空白的引用及方言约定的字幕约束。Seedream 使用图片任务自己的中文引用和编辑表达。可信前镜已采用尾帧（否则已采用视频）提供仍持续的手位、持物、接触和空间边界，不把前镜动作或终态复制为当前首帧；cut 允许换取景，持续状态仍须有交代。任务保存自身首尾 `frameContextHash` 与 `previousBoundaryHash`，收取、采用和修订前核对，旧候选不会覆盖已改变的共同状态。

编号后续只确定性映射到真实文件、节点或首尾槽位；素材用途、模式或模型方言变化时阻断并返回 Chat，不补写正文。
