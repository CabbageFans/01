## 3. 本次正文如何保存和采用

`prepareRuntime` 从当前事实构造普通 Chat 任务，绑定正式 task/run。收取先保存完整 `rawText`，再核对 requestId、精确目标集合和无损 JSON 结果；缺项或格式错误保留原文与错误，不用旧 final 补齐。格式纠正有次数上限。

未手改且事实未变的正文正常采用；用户手改 final 保留，新回复另存候选并提供明确采用入口。更换剧本、镜头、选图、模型或同目标已有新请求后，较早回复只保留为过期候选。编辑计划始终先存候选，显式采用后同时保存 `editIntent`。打开、切换、刷新和缩放不调用模型。

final、计划素材、实际引用绑定和提交快照分别保存；导出与生产共用引用编译，不从旧动作摘要重新拼正文。缺图／未知模式保持计划状态和原媒体门禁。实际媒体任务提交链有离线回归，本轮没有为文字验收新建媒体生成任务。

真实验证暴露的焦点／坐标和回读问题已修复：提交意图前检查 OS／guest 焦点、host/composer 可见、视口命中与两帧几何稳定；普通 Chat 首次仅向权威按钮派发一次 guest pointer/mouse，之后等待本次用户消息全文回执。没有补点、Enter 或自动回退。新策略已在场景、13 项镜头及后续审查／修订真实通过；早期不确定任务保留原运行，只读收取，未用新请求掩盖。
