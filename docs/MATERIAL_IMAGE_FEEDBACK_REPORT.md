日期：2026-10-30。变更：`petstory-image-feedback-flow`。工作区实际为 `/Users/dingzhenyu/Documents/01`；用户任务书中的旧机器目录本机不存在。实现验收后按用户新指令提交并推送代码；不创建 Release 或进入 P5。

## 实现

- 素材页删除提示词生成／采用／编辑、生成记录／诊断、更多及省略号菜单、批量提示词和局部编辑计划。保留人物／道具／场景、名称、用途、图片、上传、实际进度、单项恢复及真实会话入口。项目更多在本页替换为打开项目。
- 一次生成保存一个 `imageOperations` 意图。适用手改／已采用正文优先；否则沿既有 Chat、收取、有限结构修订和正式正文采用服务继续单项 Production。Chat 根任务与操作关联同次保存，历史错误候选不会自动进入本次操作，旧手改保存在原记录及请求快照。
- 修改选择新会话上传具体基图的路径。保存预览选定的 `baseAssetId`、SHA-256 和原样反馈，编译有来源的编辑请求，复用原上传、逐文件绑定、任务租约、单次原生发送、结果回读与下载链。没有伪造 Chat 回复、第二素材库或第二浏览器执行器。支持未采用、上传、旧候选、已采用及上一轮结果；主动新轮与结构修订次数分开。
- 新图与上传先登记候选，正式采用仍走原服务；旧图、历史、任务和媒体保留，下游复核沿用。没有因图片操作启动视频或全项目制作。
- Store 根据真实 Chat／图片任务推进准备、生成、保存和候选状态；没有定时伪造完成。重开仅显示保存状态，显式继续才恢复原运行；下载失败只补原产物。当前操作在本页且没有其他弹窗才自动预览，离开页面只显示待确认。
- 会话入口取当前真实阶段任务或选定图片的原任务／运行。上传图没有 AI 来源时不显示伪造链接；生成期间旧图来源不能导航抢走当前账号。
- 图片执行不再自动展开浏览器。原宿主保持非零尺寸和视口交集，正常合成并显式启用输入，由不透明工作区覆盖并接收前台用户点击；不采用 `display:none` 或卸载。相同账号 partition、Webview 和原生发送方式保留，草稿与自由 Chat 仍受保护。

主要修改：`PetStoryMaterials.tsx`、`PetStoryImageReview.tsx`、`PetStoryPanel.tsx`、`App.tsx`、`BrowserPanel.tsx`、`usePetStoryStore.ts`、`petstoryImageFlow.ts`、`petstoryBackground.ts`、`doubaoBridge.ts`、素材／全局样式；主进程 `petstoryImageOperations.ts`、`petstoryProduction.ts`、`petstoryImageReview.ts`、`petstoryChat.ts`、`petstoryProject.ts`、IPC／preload 及共享 contracts。画布布局、视频交互没有重做。

## 真实 Electron 验收

正式项目位于本机桌面。其方案实际为 **6 镜头／7 基础素材**；此前报告的原五镜头项目文件本机缺失，原五镜头／原故事夹具用于离线回归，不声称五镜头实机全链通过。未改人物设定或镜头数量。

测试副本仅复制原项目并更换项目 ID；不手工写入模型正文、生成图片或采用结果。所有新候选来自真实平台下载或正常上传，采用仅在测试副本进行。

首次及第一轮发现的真实缺口已修复：视口外只剩隐藏编辑器、调度映射瞬时缺失导致自动展开、提交意图与受理证据之间轮询误判、恢复重新读盘带回旧错误。第一轮的迟到结果通过既有只读核对取得；当时当前页补定位使用了短时开发者诊断事件，之后从可见素材按钮补下载。它不是无干预 UI 全链通过；最终代码已将同一路径接入显式继续并覆盖归属／歧义／失败回暂停测试。

第二轮现场仍出现了原生点击未取得受理回执的情况，不能从单次现象确定平台原因。最终保留视口交集、正常合成和显式 `pointer-events:auto`，以不透明工作区覆盖浏览器；没有切换发送策略。非生成诊断在临时捕获并阻止平台动作的条件下，确认覆盖区域内同一原生通道的可信 mousemove／mousedown／mouseup／click 均可达。此诊断只验证输入通道，**不等于第二轮图片产出或平台受理保证**。既有不明提交不重发，原任务、基图、反馈、输入快照及历史全部保留。
