# 图片生成与修改执行规则

## 当前规则：单任务执行（2026-11-06）

按最新用户要求，全应用一次只启动一个图片生成或修改流程。点击当刻即占用，覆盖后台文字准备、平台生成和候选保存；其他卡片“生成图片”、预览“重新生成／修改图片”及已打开反馈框的提交按钮共用同一占用状态，入口不接受第二项排队。暂停、失败或完成后释放；恢复原任务同样一次一项。

保留独立任务对话、操作归属、原始输入、历史候选及具体基图连续修改。查看、无关素材上传与明确采用继续沿原规则。此改动不新增产物抓取路径、兜底、自动重试或平台重发，不把单任务限制表述为已修复截图中的产物回读问题。

镜头首尾帧的正式图片操作及后台文字准备同样使用独立任务页，打开豆包 Chat 不再因面板可见而暂停这些任务；全应用单图片占用与原账号调度范围不变。旧已提交且缺定位的镜头任务保留原页面，不用新空白页替换。见 [关键帧 Chat 展开修复](handoffs/2026-11-06-keyframe-chat-visibility.md)。

图片准备、生成等待和候选保存期间可点击“停止”。工具立即撤销本次操作的后续执行与观察权限，通过正式任务接口保存暂停并释放占用；原任务、原对话和已有图片保留，可继续原任务，不自动重发。若图片恰好已完成保存则保留完成结果。停止不操作豆包平台的后台生成。实现与验证见 [图片停止说明](handoffs/2026-11-06-image-stop.md)。

# 历史记录：基础素材图片并行生成与修改

2026-11-05，变更 `petstory-parallel-material-images`。本说明适用于人物、道具和场景卡片上的图片操作。

## 用户行为

直接连续点击不同素材的“生成图片”，或对各自预览中选定的图片提交修改。每张卡显示自己的准备、排队、生成、保存、候选或失败状态。同账号最多两项执行，额外请求沿正式任务队列等待，输入、上传和发送仍逐项完成。

一项失败可以单独继续；已受理只观察原对话，下载失败只补下载。同素材未结束操作防重复，新的连续修改绑定选中的具体基图。新图仍是候选，明确采用后才替换正式引用。

## 实现与兼容

- `imageProductions[operationId]` 保存独立制作记录，通过操作作用域复用正式制作、上传、下载和恢复服务；保留旧 `production` 兼容。
- 只有同时具备原账号、项目、素材及图片操作绑定的准备 Chat / image 任务获得素材执行槽；同一素材始终互斥，普通任务和视频仍占用原账号范围。
- 任务页面按 taskId/runId 定位，使用原账号 partition；不复用账号自由聊天页面或另一图片页面。原消息及产物回读继续校验任务、运行和原会话。
- 每操作独立授权和观察状态；Store 图片短事务排队读取最新版本，主进程仍按项目串行写盘。某项完成或出错不会撤销其他项的发送授权。
- 上传/采用只保护真实相关素材；旧任务、原始输入、基图摘要、历史候选与明确重发关联全部保留。已提交且缺定位的失败页面保留供核对。

## 验证边界

离线回归覆盖异素材并行、同素材防重、两槽排队、乱序完成、失败恢复、具体基图连续修改、无关素材上传/采用、租约丢失、独立页面及迟到回调。另覆盖准备任务 bound／受理不明／captured／repair 检查点的原操作恢复，以及排队暂停或失败后撤销旧派发授权、只执行本次恢复授权。

## 首次人工验收故障与修正

首次人工验收出现两项 `page_unrecognized`、另外两项持续排队。原任务证据确认，失败发生在发送前，账号常驻页可用；并非平台生成耗时。

- 独立页的 `dom-ready` 早于豆包 SPA 输入区挂载，任务却先检查推广弹窗及探测账号。改为先等原页面真实输入区就绪，再执行原推广白名单检查及本页账号探测，沿用既有就绪检查和时限；就绪失败时两类探测均不执行。
- 独立页在首个文档事件前加载失败或无事件时，原派发循环一直等待。为该首载阶段补齐主框架加载失败、进程退出和15秒截止的终态，只暂停及释放尚未取得控制器的原未提交任务；已提交原结果页不受此截止影响。
- 已释放执行锁的验证／页面等待任务仍被计入两项并发容量。改为仅计实际执行、生成及持有预留的任务；同素材互斥与真实账号登录／验证码阻断继续有效。
- 原账号的多个页面共用探测序列，较晚的探测可能使另一任务读到其他页面的缓存。改为每页独立证据，只共享真实登录／验证码事实；过期页面及验证代次不能发布 ready。
- 派发前绑定保护暂停未保存机器可读原因，与未提交恢复入口的条件不一致。恢复必须基于原项目、任务、运行、原输入及零提交证据判断，不按错误文案猜测，不更改真实任务文件。

上述修正不增加自动重试、超时时长或替代输入入口。已提交和受理不明任务仍只核对原结果，图片仍需用户明确采用。
