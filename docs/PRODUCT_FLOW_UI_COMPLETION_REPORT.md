## 2. 指定截图区域具体收敛内容

“方案与提示词操作”不再成为主方案操作的前置容器，保留功能进入“更多操作”。删除普通区域中重复的当前方案长正文、独立分析候选结果卡、同轮修订父错误卡及重复回复来源。分析与它的格式修订由父请求链组织为一轮结果，原请求记录没有删除。

审阅卡默认显示一个标题、一个互斥状态、镜头／人物／道具／场景／总时长、一段截短理解和至多少量变化。主按钮为“确认并采用方案”，次按钮为“在豆包中调整”。完整故事、角色、场景与每镜字段放入“查看完整方案”的限高滚动区；时间、任务、规则和完整原回复收进默认折叠的“生成记录／诊断详情”。有新候选时提供折叠的当前采用方案对照，并明确原图片、视频继续保留。

基础素材区移走默认大统计提示框、图片入口检查、免费权益勾选、账号打开、批量准备、关键帧缺项和高级补齐入口。采用方案后，默认为必要计数、类型筛选及对象卡；相关能力保存在“生成设置／入口检查”或“更多操作”。每个素材只在当前生成动作确实被阻断时就地给出一个原因和对应处理入口。提示词缺失不会要求先检查图片入口；查看已有图片或候选也不要求重新生成。

## 3. 用户状态与主次操作

| 对象状态 | 唯一主要操作／反馈 | 次要或折叠操作 |
| --- | --- | --- |
| 方案正在生成 | 当前进度与等待事实，没有采用按钮 | 异常时在同一卡给对应恢复入口；原任务不重发 |
| 方案候选待确认 | 确认并采用方案 | 在豆包中调整、查看完整方案；诊断默认关闭 |
| 方案已采用 | 方案已采用；准备基础素材 | 在豆包中调整；没有候选采用按钮 |
| 有新方案候选 | 确认并采用方案；明确与当前方案不同 | 在豆包中调整、当前方案对照；确认前不替换当前方案 |
| 方案需要复核／回复尚未核对 | 具体问题和当前处理入口，没有可正常采用按钮 | 其他恢复动作收进更多；完整来源留诊断 |
| 方案未确认时进入素材 | 查看并确认方案 | 不投影素材生成、上传、批次或入口设置 |
| 素材无图，提示词未就绪 | 生成提示词 | 上传图片；文字请求仍须真实免费确认及原任务资格 |
| 素材有真实待采用提示词回复 | 查看并采用提示词 | 上传图片；查看候选不再创建新请求 |
| 素材无图，提示词就绪 | 生成图片 | 上传图片；阻断原因就地处理 |
| 图片候选待确认 | 查看并采用 | 替代上传、重新生成、历史和豆包调整进入更多或预览层 |
| 已采用图片 | 查看图片 | 更换、重新生成、历史版本进入更多 |
| 旧采用图需要复核 | 查看并复核；预览后确认继续使用 | 旧图持续可见；未重新确认前不计入可用采用素材 |
| 提示词有未保存修改 | 保存修改 | 放弃修改；保护其他对象和画布草稿 |
| 下载失败／原任务已有产物 | 原产物收取或重新下载 | 与重新生成提示词、重新生成媒体分离 |

这些状态来自项目、候选、采用记录、文件摘要、任务和当前检查事实。未通过改标签把候选当作已采用；已采用记录还需与当前图片、校验摘要及人物身份一致，待复核或候选图片不能误计为可用素材。

## 4. 图片真实代码路径与确认边界

豆包图片沿原 TaskService 和制作服务执行、读取与下载，文件先作为候选保存。`PetStoryImageReview` 展示具体目标、多图选择、文件检查和旧采用图对照；点击“采用这张”后才经既有 `approveMaterials` 或 `adoptShotImage` 路径回写对应素材／镜头。预览、切换候选、关闭弹窗和保存候选都不自动采用。

人物、道具、场景卡与画布首帧／尾帧提供“上传图片”。文件选择的位置确定用途，原生选择后由既有项目服务校验、复制并保存候选，随后自动打开相同预览；用户不填写内部 ID，也不需要让有效上传图经过豆包重生成。

自由 Chat 图片由选定的具体助手回复及其图片链接确定范围。现有会话、源 task/run、回复稳定性和对象版本核对后，通过已有下载服务收取，保存 `sourceReply` 来源，再进入同一预览采用流程。纯图片回复可以进入选择器；不能把任意网页图或未选回复的图片混入当前目标。

确认替换前，旧采用图和产物不变；确认后新图成为当前采用，旧图保留历史，受影响下游标记复核。未采用／失效图片仍被实际媒体资格与引用检查拒绝。本轮真实上传仅验证了人物素材：点击“噜噜”的上传入口，经原生文件选择器选择图片，自动进入目标为“噜噜·人物参考图”、来源“本地上传”的待确认预览，显示 1280×2278 和文件校验通过；“采用这张”可用，但点击的是“暂不采用”。关闭后仍为已采用 0/7、待确认 1、缺少 6，正式图区继续显示尚未采用图片。最终普通重启后，再经正常 UI 打开同一项目，候选、数量和正式节点未采用事实仍保留。**没有执行图片采用、替换或下游引用；道具、场景、首帧和尾帧的实际上传尚未逐类验收。** 这些离线及局部真实验证不等于真实媒体链通过。

## 5. 自由 Chat 的具体回复路径

从方案、基础素材提示词或某镜首帧／尾帧／视频提示词点击“在豆包中调整”，传入该对象或具体方案候选，沿现有服务打开其原账号、原运行关联的同一会话并保存目标。文字仍采用仓库已有的工具自动发送方式；本轮没有把文案改成人工发送实现。

自由聊天期间，既有任务台账与会话保护阻止后续自动注入、草稿覆盖和会话切换。工作室读取可核对的助手回复列表，用户主动选择具体回复，没有默认最后一条。点击“应用到当前创作”先显示目标及完整回复／拟应用正文；确认采用时再次核对源会话、具体回复、版本和未保存草稿，随后只更新目标、保存并回填。需要结构整理时由用户继续在豆包交流完成，程序不补写创作正文。

图片回复另外提供收取候选入口，收取后仍须在图片预览层点“采用这张”。回复文字的确认不自动采用其中图片。本轮没有在原用户会话中执行多轮聊天、选择并采用文字或图片；错会话、迟到回复、纯图片回复、目标隔离和采用边界由离线行为／DOM 测试覆盖，真实平台操作待验收。
