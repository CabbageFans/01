# PetStory Studio 当前增量：分镜拆分与5～10秒镜内节奏（2026-11-05）

本节与 `storyboard-pacing-optimization` 为分镜节奏的有效要求，覆盖历史方案固定镜头数、无条件保留旧镜头结构及改时长可无条件复用旧正文的冲突条款；保留当前画布、后台进度、自然语言反馈、候选明确采用和角色图优先规则。实施与验收见 [STORYBOARD_PACING_OPTIMIZATION_REPORT.md](./STORYBOARD_PACING_OPTIMIZATION_REPORT.md)。

- 每镜 `durationSeconds` 只允许有限数值整秒5、6、7、8、9、10；分析、保存、采用、手动编辑、修订、批次和实际任务一致，页面选项只取产品范围内可用值。旧特殊值只兼容读取，不用于新生成。
- 普通豆包 Chat 先读完整剧本并落实原文来源及信息／情绪变化，再组合自然镜头、安排必要动作和发声的先后／并行，选择最短够用时长。不得默认8／10秒、统一5秒、设置镜长比例、机械相加可并行事件或固定头尾等待。原稿秒标签仅为来源节拍线索。
- 新完整方案具有 `timingPlan`：事件相对时间窗口、对白数组对应、必要前置关系、估计时间、镜长依据和切出位置；其为制作安排依据，自由文字 `timing` 只兼容旧方案摘要。合法时间表不等于创作品质合格，不保证模型逐秒精确执行。
- 完整原句按出现次数与 Unicode 字符半开区间关联对白片段，保持逐字台词、说话者、发声方式与有意重复。原始回复中整句逐字相同时可同时省略区间两端，由程序计算完整范围并保存；片段必须显式给范围，已提供的错误范围仍拒绝。超过10秒的必要内容先去装饰性动作并考虑真实可并行行为，仍过载则自然拆分为各5～10秒；不删台词、快读、倍速或使用段内多镜容器。
- 完整方案反馈明确要求节奏调整时可合理拆镜、合镜和改时长；职责不变保留ID，拆合使用新ID及必要前身关联。`assets`只补资产，单条正文反馈只改目标，不重排全片。新方案先候选，采用前保留当前方案和媒体，采用后仅更新实际受影响镜头及连续依赖。
- 时间安排贯通请求、返回解析、候选保存、采用、重开与设计快照。首帧只画可行动起点，尾帧以首帧编辑得到必要终点，视频实现采用的动作链、逐字对白、反应、时间安排与运镜，不再增加无来源铺垫。显式改时长／事件安排后匹配正文经原入口自动准备；已发送任务快照与历史媒体不改写。
- 仅对非法数值、时间窗口、顺序、引用及明确对白遗漏／重复走既有修订，不增加节奏审批、免费确认或新技术面板。旧无新字段项目可正常打开。程序不代写创作正文，不加TTS、第二执行器、数据库、合成／自动剪辑或发布。
- 真实文字验收仅在同一原故事的隔离项目经可见UI执行。报告分别标明离线、真实UI、真实Chat与真实媒体的验证边界，无新视频不得声称成片节奏已实测改善。

## 4. 十一项必做需求

### R01 来源输入：手机豆包故事回填

### R02 普通 Chat 附件、正文与结构化结果

- 接通普通 Chat 对已粘贴故事的处理和可选角色参考图附件，准确提取本次助手最终答案，保留换行和代码块；不读取整页文字充当答案。

- 输出原片简述、一份改编故事及所需镜头。保留关键事件关系、人物动机、冲突、转折和结局逻辑，允许调整场景、道具及具体表达，不只保留题材标签。

- 制作前允许修改文字、增删／调整镜头顺序；使用简单列表按钮即可，不做时间线编辑器。增删后检查关键情节和引用，不静默删掉主线。
- 媒体制作后整体换故事或核心角色，首版可新建项目；局部修改按 R10 处理，不建完整版本体系。

### R04 固定主角＋按需配角

- 固定主角为“噜噜”“噜妹”，使用用户提供的参考图和简短设定；保持身份、外观与服装，不强制每镜头二者同框。
- 原故事需要店员、朋友、家人等第三方参与时，允许新增配角；角色数不硬编码为2，也不人为改成3或4的固定上限。
- 每个可辨识配角保存：ID、名称、剧情作用、简短外观、参考图。用户可提供参考图；未提供时，在已确认计划内用豆包生成一次项目内参考图并跨镜头复用。
- 只生成必要配角，普通背景人群无需逐个建立档案。不为增加“丰富度”擅自扩充人物。
- 明确参考素材与角色映射；仅上传当前镜头需要的图，区分谁做动作、谁持道具、谁位于左右位置。多人构图必要时先用 Seedream 生成一张完整场景帧，再交给视频入口。
- 附件限制或复杂同框无法满足时，提出拆镜／简化站位方案，不悄悄漏人或把配角并入主角。
- 主角配置可复用，项目复制所用角色图；配角保存在本项目，不建设人物商城、多角度向导或版本库。

### R05 生成并绑定镜头关键帧

- 首帧路线：用当前镜头角色参考、场景和优化提示词生成首帧，或者按已批准的连续关系复用上一视频实际末帧。
- 首尾帧路线：生成／取得首帧后，以该首帧为编辑参考生成尾帧，明确只改变动作终态所需部分；不默认独立生成两张毫无关联的图片。
- 两帧宽高比一致。角色身份、服装、场景布局、光线、道具与机位应符合分镜；剧情明确要求改变的部分除外。
- 首帧与尾帧分别保存、分别绑定；不把双图拼贴当成一张合法首帧，不把角色肖像当成镜头结尾状态。
- 一次返回多图时采用明确固定的有效图选择规则并显示选中图；允许替换，不新建候选图库或 AI 打分器。
- 所有关键帧完成必要的文件校验并下载到本地，才允许下游使用。只为实际选择首尾帧的镜头生成尾帧，避免无谓增加图片请求。

### R06 按镜头选择视频模式，区分两类连贯性

| 镜头需求 | 推荐方式 | 需要注意 |
|---|---|---|
| 表情、轻动作、结尾构图无需精确指定 | 首帧；无专用首帧入口时采用实际支持的参考图模式 | 首帧与一般参考图要如实区分。 |
| 同场单段动作有重要终态，如交接礼物、开盒、落座 | 首尾帧用途，复用本镜已采用两图；按当前入口真实绑定 | 起止状态可在给定时长内合理连接，提示词必须写清中间动作；只有明确原生槽要求才限定专用槽。 |
| 与上一段同场同机位、动作直接延续 | 前一选中片段的实际末帧作本段起点；终点重要时再加尾帧 | 不能直接把上一段“计划尾帧图”当作视频确实到达的结尾。 |
| 换地点、时间跳跃、正反打、景别或机位明显变化 | 正常切镜＋角色／场景状态约束；单段模式另行选择 | 不为追求所谓无缝而强制插值，或让镜头不合理地穿越场景。 |

- 所有镜头都设计开始／结束的**文字状态**，但不是每个镜头都必须生成两张图片。
- 首尾帧主要帮助单段起止控制；跨镜头还需角色、道具归属、人物位置、视线和场景关系一致。该策略是工程选择，不承诺中间运动绝对正确。
- 运行时回读当前普通入口。已采用首尾两图可通过独立首／尾槽或统一多图入口按同一图片、原顺序与真实引用绑定上传；生成／继续保持原逻辑模式，不要求额外授权或手动改成参考图。实际上传方式记录在 `pageBindings`，统一多图不能标为原生独立首尾槽。
- 仅正文明确要求原生首尾帧、独立首／尾帧槽或首尾帧专用槽时，才必须核对对应原生槽；入口缺失或平台实际拒绝时保留原任务并显示真实原因，不擅自改模型、正文或模式。普通起点、终态和两图用途描述不能触发原生槽限制，也不能因统一上传入口要求用户重新选图、确认或生图。历史额外两图授权只兼容读取，不新增按钮。
- 依旧只调用现有 Studio 提交与下载链。模型、时长、比例以当前入口为准，不调用方舟、即梦或其他付费 API。
- 连续接力使用 FFmpeg 抽取上一选中视频有效区间的最后可解码帧，绑定为真实资产；不使用黑帧、过期候选或未选中的视频版本。
- 生成完成后保存实际时长、尺寸和本地文件；缩略图不等于 MP4。文件损坏或未生成时暂停，不填假素材。

### R07 顺序制作、恢复与数量提示

- 对动态 `shots[]` 顺序执行：必要角色图 → 当前镜头关键帧 → 视频 → 下载 → 下一镜头；不建立新的并发系统。
- 开始前显示实际镜头数、配角数、计划新生角色图／首帧／尾帧数量和视频请求数。复用图片不重复计为新生图；计划不是官方额度余额。
- `project.json` 保存故事、角色、分镜、输入来源、既有 taskId、素材路径和进度。通过现有服务写任务，不直接篡改 Studio 运行中的任务文件。
- 已有有效素材跳过；下载失败只重试下载；已受理继续观察原会话；受理不明不自动重发。
- 暂停／重开后由用户点击继续，沿用已有状态与任务身份。平台实际返回额度不足时保留所有完成结果；不根据本地预测提前阻断。

### R08 零额外模型费用

- 全部 AI，包括新增提示词优化和配角参考图生成，都只走豆包普通对话／创作入口。
- 不配置模型 API Key、不新增本地 AI、不安装需要终端用户运行的 Codex／Claude／OpenCode 宿主。
- 提示词优化模块不得调用 GitHub 工具原有的外部模型、代理接口或收费生成脚本。
- 用户确认创作计划后可直接开始；不核对免费声明、人工入口检查或本地预测余额。平台本次实际返回额度不足、会员限制或其他拒绝时显示真实原因并保存进度；不自动购买、充值或订阅，不硬编码每日6单位。
- 上传、候选预览与采用、已有素材下载、导出和本地操作不访问生成入口；不为了同日出片删情节或轮换账号。

### R09 本地顺序合成 MP4

- 只用 FFmpeg／ffprobe，复用现有安装；无需 Remotion、字幕引擎或新渲染服务。
- 合成所有选定的有效镜头，不假设数量。输出9:16 MP4，统一编码、尺寸和帧率，优先留边而非任意裁掉主体。
- 保留可用原生音轨，无音轨允许无声；不接外部 TTS。首版不做配音、多轨混音、字幕编辑器或复杂转场。
- 连续拼接只做必要的切点处理与预览，不增建光流补帧等系统；硬切镜头不强制融合。
- 提供播放和“在 Finder 中显示”。不以静态图移动、循环片段或黑屏替代缺失剧情；1080P画布不冒充素材原生1080P。

### R10 预览、局部重做与简单保存

- 动态镜头卡显示角色、模式、首帧、可选尾帧、视频、状态、优化后提示词和“重做”。
- 修改动作只重做有关视频；修改关键帧则重做使用它的视频。原素材保留，不覆盖无关镜头；成功后重新合成。
- **连续接力例外：** 后镜头若明确引用了前镜头旧末帧，前镜头重做后应提示该关联已过时；不能一边声称接力连贯，一边静默沿用失效起点。
- 仅标记明确依赖的后续镜头，由用户选择保留旧素材正常切镜，或重新绑定并重做受影响的连续段；不自动整片重做，不开发通用依赖传播框架。
- 保存／打开普通目录和 JSON 即可。不做项目 ZIP、跨设备迁移或完整历史管理。
- 内容质量由用户预览判定，不新增豆包逐帧质检链；优化建议不自动触发媒体重生成。

### R11 内置 Seedream／Seedance 提示词优化

**必须实际接入生成流程，而不是只给用户两个链接或要求复制到其他软件。** 默认优化，可查看修改前后；手动编辑后的文本保留，并提供“重新优化”按钮，不反复覆盖用户修改。

**两类优化分别处理：**

- **Seedream：** 明确角色与参考图对应关系、外观不变项、单帧动作状态、构图、场景、道具、光线与画幅；尾帧说明相对首帧改什么、保留什么。避免一张图承载多段先后动作和多格分镜。
- **Seedance：** 明确谁做什么、动作起止及中间过程、持物归属、镜头运动、连续／切镜关系；避免多项矛盾运镜、过多同时动作和模糊代词。原生首尾帧与一般参考方式分别编写，不混淆。
- 先用确定性规则检查缺少角色图、错误引用、首尾顺序、空提示词和模式不匹配；需要语言优化时，将规则与当前分镜交给豆包普通 Chat。
- 默认在首次故事／分镜回复中一并产出优化后的提示词；结构完整的分镜不必每镜头追加一轮“优化对话”。用户调整后仅优化选中镜头。
- 不修改已经确认的主要情节、角色身份或关键动作，不强行添加台词、音乐、夸张镜头和风格词。明确冲突需要改分镜时，展示修改建议，不悄悄改故事。
- 人物参考实际上传顺序与提示词对应。仅在网页真实支持时使用对应的引用语法；不把即梦／API特有的 `@Image`、模型 ID、参数原样塞给豆包并假定生效。

**已核查的 GitHub 复用候选：**

| 用途 | 项目与文件 | 本轮集成方式 |
|---|---|---|
| Seedance 视频提示词 | `silentbuilds/seedance-prompt-forge`：`skills/seedance-prompt-forge/SKILL.md`、`references/reference-materials.md`、`references/advanced-modes.md`、`references/checklist.md` | 提取主体动作、参考角色映射、起止状态、模式区分和检查规则；该包面向2.5，不把其版本专用能力当当前豆包网页实际支持。 |
| Seedream 图像提示词 | `a86582751/doubao-seedream-image-skill`：`SKILL.md` 的 Prompt Optimization Rules、`references/prompt-guide.md` | 提取清晰自然语言、主体/场景/构图、编辑保留项和多图映射规则；不集成其方舟 API 调用、密钥读取、Windows路径或付费生图 CLI。 |

两个仓库均已读取实际 MIT LICENSE。开发时固定采用的 commit、保留所复用代码／文本的许可说明即可；不导入整个工具生态、不建设在线插件市场。外部 Skill 是待改编的规则资产，不覆盖本项目需求。[S3][S4]

## 5. 最小界面、数据和开发边界

**一个“萌宠短剧”页签即可。** 上部是链接、手机提示词、故事回填、两位主角、按需增加的配角和方案按钮；中部是故事和动态镜头列表；下部是开始／暂停／继续、局部重做、成片播放与导出。提示词和模式详情折叠，不新建优化器页面。

**一个 `project.json`＋本地素材。** 不迁移数据库；保留既有 Studio 任务身份与状态。

```text
project/
  project.json          # 角色数组、镜头数组、状态、taskId、提示词和引用关系
  # 来源链接、手机故事原文和导入时间保存在 project.json，不保存来源视频
  characters/           # 固定主角与本项目必要配角
  shots/<shotId>/        # 首帧、可选计划尾帧、视频、可选实际末帧
  exports/              # 最终MP4
```

分镜的最小业务字段：

| 对象 | 字段 |
|---|---|
| 项目 | `sourceSummary`、`adaptedStory`、`characters[]`、`shots[]` |
| 角色 | `id`、`name`、`role: main/supporting`、`description`、参考图关联 |
| 镜头 | `id`、`order`、`characterIds[]`、`scene`、`action`、`durationSeconds`、`startState`、`endState` |
| 连贯与模式 | `transition: cut/continue`、可选 `previousShotId`、`requestedMode: auto/first_frame/first_last_frame/reference`、实际 `resolvedMode` |
| 提示词 | 原始与优化后的首帧／可选尾帧／视频提示词、采用的规则版本 |
| 运行结果 | 当前选中关键帧／视频、可选 `startFromPreviousEnd` 及其具体源视频、taskId、进度和导出路径 |

模型只返回故事数据和逻辑引用。实际路径、媒体参数、任务 ID、最终模式由程序根据真实页面与文件关联，不让模型伪造。`plannedEndImage` 与 `actualEndFrame` 必须区分。

实现仍使用 Electron／React／TypeScript、原服务与文件存储；不开适配器大重构、SDK、插件系统、MCP或HTTP接口任务。保留既有登录隔离与防重复提交，不为赶时间删除。

## 6. 六小时开发安排与停止规则

本表是总计360分钟的开发投入上限，不是对未知网页行为或平台生成速度的保证。本次新增功能通过数组、规则文件和少量现有流程分支实现，不扩成新平台。

| 时间段 | 工作 | 结果 |
|---|---|---|
| 0:00—0:20（20分钟） | 读取现有工作树、一次拆分一个 Spec Kit 增量；查看首尾帧入口和已有能力 | 确定复用点，原生首尾帧可用／不可用／待用户确认；不重新迁移 Mac |
| 0:20—0:50（30分钟） | 链接、手机提示词和故事回填 | 保留来源与手机故事原文；不继续网页解析或本地原视频支线 |
| 0:50—1:55（65分钟） | Chat附件、正文、相似故事、动态分镜和配角数组 | 可变长度结构化结果，主角身份固定 |
| 1:55—2:30（35分钟） | 移植两类优化规则与轻量检查，接入豆包Chat | 提示词实际参与后续生成，不装独立优化平台 |
| 2:30—4:10（100分钟） | 角色图、关键帧、视频自动接力；首尾帧和连续关系分支 | 用现有任务链完成输入绑定；无入口时明确降级，不研究破解 |
| 4:10—5:00（50分钟） | FFmpeg合成、预览、局部重做和关联过时提示 | 动态数量的镜头可合成，重做范围清楚 |
| 5:00—5:25（25分钟） | 最小页面、保存继续、额度提示整合 | 除一次手机故事回填外，用户不用逐镜复制搬运中间结果 |
| 5:25—6:00（35分钟） | 必要构建／相关测试、修复阻断、交接用户手动验收 | 实际完成清单和剩余问题 |

只做一次页面能力确认。入口不存在、收费或短时检查无法确认，不占用整个时间盒寻找隐藏接口；保留分支说明与可用模式。若只是适配代码未完成而平台实际支持，必须记“实现缺口”，不能谎称平台不支持。

源路径未接通、某原生模式未适配或提示词优化未接入时，逐项列缺口。第五小时后不加新功能；第六小时停止扩展并交接。不通过恢复“三镜头／仅双角色”来缩工，不以付费模型、假JSON、历史视频伪造通过。

## 7. 八条验收，由用户确认实际效果

Codex负责构建和相关离线测试；用户手动执行真实账号及视频内容验收。离线样本与模拟限制只证明程序规则，不冒充真实生成。

| 编号 | 必须看到的结果 |
|---|---|
| A1 手机故事回填 | 保存抖音链接并复制对应手机提示词；用户在手机豆包取得并核对故事后粘贴回工具，再形成制作方案。无故事不发桌面请求；原文和来源保存重开一致，无原视频入口。 |
| A2 动态故事 | 不同故事能得到不同数量的有效分镜，至少包含一个非三镜头样例；不截断、不固定15秒，关键因果和结局保留。 |
| A3 主角和配角 | 噜噜、噜妹始终是固定主角；一个需要第三角色的样例保留配角，并在出现它的多个镜头复用同一身份和参考图。 |
| A4 提示词优化 | Seedream与Seedance采用不同规则，能看到优化内容，生成任务使用优化后的最终文本；故意错绑角色或缺尾帧能被检查发现；不调用外部模型。 |
| A5 模式与接力 | 已选首尾两图经原生成／继续单入口复用，独立槽与统一多图分别记录真实绑定，不改模型、正文或逻辑模式；仅明确原生槽要求才限定专用槽，真实失败保留原任务。连续段用真实选中视频末帧，换场景不强制接力。测试请求绑定、两图顺序和文件归属，实际连贯程度由用户看成片确认。 |
| A6 完整成片 | 动态数量镜头自动生成、下载、关联并合成可播放9:16 MP4；不是图片集合或分散片段，无需人工搬素材。 |
| A7 开始与继续 | 不新增外部付费接口或购买操作；免费未知和历史检查记录不阻断开始／继续。平台实际拒绝时保存结果，恢复不重复完成任务。 |
