## 基线、来源与根因

基于当前 main，HEAD `5d2cb9e928ee1c59cf201b47a6608cf642fdb678`；开始时只有任务包未跟踪，未回退、迁移或覆盖既有改动。本 Session 只查看了任务包六张 JPG 与 REFERENCE_ANALYSIS，没有原视频，没有重新观看未提供的素材。

已只读提取桌面“测试”revision43（5镜头）及“P4-真实验收-20261025”revision20（1镜头）的现有提示词与附件用途到 [BASELINE_SAMPLES.json](prompt-quality/BASELINE_SAMPLES.json)，附项目文件 SHA-256；原项目文件未写入。

1. **优化器缺角色档案。** 原单项 optimizationPrompt 只传故事、shot、final；角色 description／当前造型未传，更没有专用外观预设。规则通用，不能让名字自动代表完整形象。
2. **引用跨阶段复制。** 原“测试”首镜视频 final 为“角色：第1张参考图噜噜，第2张参考图噜妹”；第二镜尾帧也称“第1张参考图噜噜…第2张参考图噜妹”。P4 实际视频上传场景首帧，尾帧编辑仅上传首帧。已有预检能拒绝部分错绑，却没有统一用途编译来避免它。验收副本曾人工修正这一问题，不能将该修正说成本轮新生成验证。
3. **图序来源不同。** Chat 从 assets 数组筛选，P4 按 characterIds／选中 referenceAssetId 组装；容易让一次优化所见图序被错误照搬到生成阶段。
4. **手改保护不足。** applyOptimization 仅比较 final 是否等于请求时文本；请求前已经 edited=true 仍可能被覆盖。现在检查请求前／当前 edited、正文及镜头／角色／参考上下文版本，只保存候选；显式采用后保存。
5. **全文校验过宽。** 原编辑器校验合并全部空白；TaskService 创建还会 trim 首尾。现 PetStory 显式使用 exact 回读，正文仅规范 CRLF／CR 为 LF，保留首尾空白、中文、引号和段落；多个可用编辑器、丢段、丢字或台词变化均不提交。

没有发现全局将提示词 slice 到固定字数的逻辑；部分 substring 仅作日志诊断／UI显示。50000上限属于手机故事输入，超界拒绝而非截断。原 JSON 解析与缺 optimized 已会报错，本轮保留该 fail-closed 行为，不增加短模板回退。没有把所有短文本认定为错误。

- `main/utils/petstoryPresets.json`：可编辑的身份锚点、默认造型、共同3D风格；完整橘子／草莓短裤属于噜噜，荷叶帽／衣装／盘环双叶芽饰属于噜妹。斗篷不作永久身份。新项目保存预设，旧项目打开不迁移写入，显式优化才使用补充规则。
- `src/utils/petstoryPrompts.ts` 和原两份 MIT 规则：首次分析、一次修正、单项优化都带角色资料；本镜只注入出场角色，保留必要配角。单帧起始瞬间、终态编辑、连续表演和端点连接各有独立要求，不硬套三个节拍、不新增台词或声音系统。
- 现有角色 description 是已确认项目描述；新增 shot.appearanceOverrides 保存当前场景造型。明确变更项优先，参考定义当前外观；预设只补空白，不覆盖确认换装／手写 final。主体形体、服装装饰、镜头动作与共同风格分开。

## 最终提交链路

1. 分镜／角色／当前造型 → analysisPrompt 或 optimizationPrompt → 原普通 Chat 的有序身份参考附件。Chat 图序只用于优化输入，不能沿用为视频图序。
2. 原任务完整正文 → parsePetStoryAnswer／validatePetStoryPlan → original／optimized／final；缺结果或截断 JSON 保留原文并报错。
3. 用户 final 编辑 → savePlan → 原子 project.json → 再打开回读。重优化仅对未手改且上下文不变的目标自动采用；手改后只更新 optimized 候选。
4. P4 resolvePetStoryMode（仍依赖真实能力和批准备选）→ compilePrompt（只读取 final）→ 真实 assetId／purpose／order／slot 清单 → 验证本地素材 → finalTaskInput → TaskService 创建／复用单个 hold 任务。
5. production.steps[].compiledPrompt 保存 text／final／规则版本／请求与解析模式／引用清单；P3 drafts 也保存同一编译结果。任务启动由原 useTaskStore 将全文写入 runtime.input.prompt 与 exact 标记，P4 guard 比对当前编译快照、原任务、附件顺序和模式。
6. BrowserPanel 原上传链 → 网页输入 → exact 全文回读／附件及槽位回读 → **持久化提交意图 → 单次发送 → 平台回读**。提交前再次检查正文；不一致未发送，不盲点重发。未改变未知受理／登录／验证码／授权／免费门禁。
