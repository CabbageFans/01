## 已确认的产品决定

1. 产品名：**短剧工作室**。
2. 主工作区标题：**创作工作台**。
3. 原“萌宠短剧”功能名称统一改为 **短剧创作**。
4. **取消通用创作功能，不保留其导航、页面、入口或引导。**
5. 产品核心路径：输入剧本 → 确认方案 → 准备基础素材 → 制作关键帧 → 制作镜头视频 → 查看成果。
6. 保留现有短剧画布、豆包 Chat、素材确认、提示词、任务恢复、下载与结果能力。
7. 这一步只做设计，不修改应用源码，不改业务逻辑，不运行产品测试，不执行 OpenSpec apply。
8. 先让用户看到并确认完整 UI 方案。确认前不能进入正式开发。
9. 用户确认后，UI 进入冻结状态。后续 Codex 任务不得自行改布局、视觉、按钮规格、文案、导航、信息层级或交互呈现；如业务实现遇到阻碍，先按既定设计实现，不得擅自重设计。只有用户明确授权才能修改 UI。

## 设计验收要求

### 品牌与文案
- 所有品牌标题统一为“短剧工作室”。
- 工作区主标题统一为“创作工作台”。
- 所有“萌宠短剧”用户可见功能名称改为“短剧创作”。
- 不出现“UI 提案”等设计阶段字样作为正式产品文案。
- 完全移除“通用创作”功能及相关入口。
- 禁止面向开发者的标语，例如“让用户不必理解内部状态机”“按需要你做什么组织任务”。用户可见文字只说明当前内容、实际进度、具体原因和下一步操作。

### 视觉系统
- 全应用统一页面背景、面板、文字、边框、状态色、间距、圆角、阴影、字体层级。
- 统一按钮高度、字号、左右内边距、圆角和图标尺寸。主操作、次操作、卡片操作、文字操作有清晰且固定的规格。
- 每个上下文最多一个主按钮；低频操作收进“更多”；删除重复、同义、无必要的显式按钮。
- 不使用不同大小的按钮混在同一行；不混用浏览器原生按钮与设计系统按钮。
- 所有前端页面都要有一致的设计语言：总览、短剧创作六阶段、画布、任务中心、素材与下载、账号与浏览器、设置与诊断。
- 画布是短剧生产核心，不要为了统一而破坏其节点关系；应统一节点标题、间距、操作区和状态表达。
- 不新增业务功能，不删掉仍需保留的短剧能力；只重新组织显示优先级。

### 交付物
1. 更新后的可交互 HTML 原型，覆盖所有当前实际页面；移除通用创作页面。
2. 完整设计规范，列出颜色 token、字体、间距、按钮尺寸、状态样式、各页面布局和按钮清单。
3. 用户可见文案清单，确认没有开发者视角标语、测试文案和内部实现术语。
4. 一份“功能保留／入口合并／入口隐藏”对照表，证明没有误删短剧功能。
5. 设计冻结说明，写清用户确认后 UI 不再被后续 Codex 任务擅自修改。
