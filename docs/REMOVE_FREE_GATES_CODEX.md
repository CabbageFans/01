本轮直接改代码，不重启 Product Design，不生成新视觉方案，不重做画布。当前已批准 UI 中上述检查区域属于本次明确授权删除的范围。

## 2. 要达到的用户体验

用户点击“分析剧本”“生成提示词”“生成图片”“生成视频”或“继续制作”，就进入相应任务。

不再要求用户：
- 勾选普通 Chat 免费可用。
- 勾选图片／视频和所选规格免费可用。
- 手动点击检查图片入口、检查视频入口。
- 每次重开项目重新声明或核对免费权益。
- 确认“检查不会生成”“勾选仅记录本人核对”“不代表官方额度”等说明。
- 为正常素材引用再勾选一项免责式同意。

执行器仍需读取真实页面控件、设置模型／时长／比例、上传文件和识别实际回复。这些是执行动作，不是用户必须先完成的独立检查流程；无需新增按钮或确认弹窗。

不读取不到免费标记就拒绝任务，不用本地估算额度或历史未知状态阻断任务。平台实际拒绝、登录失效、控件确实不存在等情况，只在发生时显示简短真实原因。此变更不新增购买、充值、订阅或支付操作。

## 4. 前端：移除整个检查交互，不是折叠

删除截图中的两类免费确认复选框、图片／视频入口检查按钮、检查状态、检查时间、免责说明和专用恢复提示。

“生成设置／入口检查”如果只剩这些内容，整个容器和分隔线一起删除。仍有用户实际使用的模型、时长、比例等配置时，只保留配置，名称简化为“生成设置”。不要把已删除的检查搬进高级菜单或首次使用弹窗。

“打开绑定账号豆包”从这个检查区域移除。全局“豆包 Chat”、对象的“在豆包中调整”和真实登录处理入口继续保留，不重复增加一个账号按钮。

保持现有画布布局、节点顺序、缩放平移和全文编辑。清理删除后留下的空白、无意义提示框和重复状态，不借本轮重设计其他页面。

## 5. 状态与任务：删除限制的真实依赖

### 普通 Chat

所有正常文字入口不再依赖 `freeChatConfirmed` 或任何改名后的等价变量。覆盖首次分析、基础素材提示词、关键帧／视频提示词、批量生成、手动修订、自动修订、自由对话结果整理和原任务继续。

自动修订不能因为免费勾选消失而不触发。沿用已有修订次数和任务关联；本轮不重做自动修订引擎。

### 图片与视频

`generateMaterials`、`generateShotMedia`、`previewProduction`、`startProduction`、`resumeProduction` 及其实际服务，不再要求用户先产生“本会话已检查”标志。

前端按钮和后端只读资格检查不能再以缺少 capability 快照、免费证据或人工检查记录为阻断理由。

如果目前任务创建、模式解析或提示词编译依赖页面数据，需要把正常数据读取接入用户已经启动的执行链：

```text
用户点击开始
→ 创建／接续同一任务
→ 执行器准备页面并读取必要控件
→ 按实际模型、时长、比例和模式组织输入
→ 上传并发送
→ 读取结果
```

不要在页面加载、打开项目或只读渲染时到处探测；不要为每项节点建立一套新的检查任务。复用现有执行器。

读取必要控件失败时报告具体事实，例如“当前页面没有找到视频生成入口”，不能再显示“请先确认免费”。不能用“免费 unknown”替代真正的控件不可用结论。

### 批次、暂停、恢复和账号调度

单项、批量、自动接力、重开后的继续制作使用同一规则。不能只修单项按钮，批次仍卡在旧检查。

删除本地预测额度、历史免费标志和会员猜测对启动／调度的阻断。原平台明确返回的额度不足或会员限制作为本次失败事实展示，不伪装成成功，不无限重试，也不按本地估算制造限制。

恢复已发任务、下载既有产物、导出、上传本地图片和采用图片，都不需要检查免费或访问生成页面。

## 6. 主进程与合同：不伪造“全部免费”

清理 `petstoryProduction.ts` 中将 `capability` 缺失、`image.free !== 'free'` 等作为生成资格的分支，以及实际创建任务、运行、恢复时的等价判断。

清理 `petstoryModes.ts` 中把模式“可用”定义为“支持且 free”的逻辑。模式选择依据实际控件支持和用户请求，不依据免费标签。保留当前业务所需的模式、时长、首尾帧及素材对应，不借此改变既有剧情时长规则。

将“当前免费入口可选”“已核实免费选项”等文案改成准确的操作结果，或者在不再需要时删除。

`PetStoryCapability` 等结构中混合了两类内容：
- 正常数据：账号、模型、比例、可选时长、实际槽位和模式。
- 本轮废弃内容：免费证明、用户声明、本会话检查通行标志。

去掉后者的运行时职责，保留前者在执行中确实需要的数据。同步调整 contracts、IPC、preload、类型、序列化、资格检查和调用者，不留下必填废参数。

禁止用以下方式假装完成：
- 把 `freeChatConfirmed`、`capabilityCheckedInSession` 永久设为 true。
- 把所有 `.free` 写成 `'free'`。
- 给旧项目补造免费证据或检查时间。
- 改名为“准备完成”“用户已授权”后继续要求同一类勾选。
- 删掉判断后，靠异常捕获静默跳过整个任务。

## 8. 不误删用户明确要求的创作确认

本轮删除的是免费声明和人工入口检查，不是取消用户选片权。继续保留：

- 用户确认创作方案。
- 豆包生成或用户上传图片先作为候选，用户采用后才进入正式节点。
- 用户选择具体 Chat 回复后应用到正确对象。
- 保护手改内容、已有图片视频和实际文件归属。
- 确实缺文件、未登录、实际控件不支持等必要操作处理。
- 任务已经提交但结果不明时不重复发送；下载失败只重试下载。

这些已有行为不新增面板、不额外加免责文案。也不要借“去防御”删掉修复刚完成的任务关联、自动修订、保存恢复或图片候选机制。
