## 4. 必须复刻的页面布局

### 4.1 整体结构

与截图保持相同的信息组织：浅色网格画布、白色圆角节点卡片、克制的阴影、青绿色主要操作。

```text
固定顶部：项目名 / 保存与执行状态 / 基础素材 / 生成全部提示词 / 制作控制 / 打开豆包 / 画布缩放

左侧故事卡             右侧每行一个镜头，同列对齐
┌ 原剧本与当前故事 ┐    [分镜1＋生图提示词] → [首帧/可选尾帧图片] → [视频提示词/运镜] → [镜头视频]
│ 查看、编辑、保存 │    [分镜2＋生图提示词] → [首帧/可选尾帧图片] → [视频提示词/运镜] → [镜头视频]
│ Chat生成状态    │    [分镜3＋生图提示词] → [首帧/可选尾帧图片] → [视频提示词/运镜] → [镜头视频]
└────────────────┘    ……按真实shots[]渲染

同页面上方或左侧延展区域：基础素材卡组
[人物：提示词＋确认图] [道具：提示词＋确认图] [场景：提示词＋确认图]
```

基础素材卡组是为保留现有“先确认人物/道具/场景”的功能增加的布局，不是声称截图已经展示该区域。可折叠，但展开仍在同一页面，不能必须跳到别的设置页找提示词。

不要把最终实现变成普通长表单或只有卡片外观的静态HTML。必须是可平移、缩放、聚焦、编辑并接入真实数据的工作画布。

### 4.2 故事卡

展示当前用户原剧本及已有改编故事，可查看全文、编辑、保存。保留已有Chat生成入口。

用户确认过的故事不在打开页面时自动重写。此次五镜头测试只重新生成提示词，不擅自换剧本或重新拆镜。

### 4.3 分镜/生图提示词卡

显示镜头序号、实际时长、场景、出场角色、关键道具、起止状态、相关原台词。

直接显示本镜头最终生图提示词。需要尾帧的镜头同时显示尾帧编辑提示词，清楚标出用途。不为了模仿截图删掉现有首尾帧能力。原组件把场景输入限制为4个字，本项目不要照搬；场景名称/内容与景别分别显示，不能把场景细节截成“全景”之类标签。

支持完整阅读、复制、手动编辑保存及“豆包重新生成本项提示词”。不把图片提示词缩成一两句摘要，不截断实际存储和发送正文。长内容可以卡内滚动和就地放大查看，不能只剩省略号或藏在JSON里。

### 4.4 图片卡

显示豆包实际生成并下载的图片，首帧与可选尾帧分别标识。下方显示本次采用的人物/道具/场景缩略图及用途，区分选用图和生成图。

支持现有图片生成、预览、下载及用户明确点击的重新生成。下载失败按钮只重新下载，不重新生成。

基础素材沿用用户确认机制；关键帧引用已确认素材。原有参考图可继续导入与复用，并注明来源；新生成图片只能来自豆包。

### 4.5 视频提示词/运镜卡

直接展示当前最终Seedance视频提示词全文，包含已有正文里的动作、表情、台词与运镜，不只显示“固定机位”之类运镜字段。

显示请求模式、当前实际模式、请求时长、首/尾槽或参考图清单。已有引用标签按实际映射展示，不新增本轮提示词改写规则。

提供“豆包重新生成视频提示词”、复制和手改保存。提示词重新生成与视频重新生成是两个不同操作，按钮必须分别命名。

### 4.6 镜头视频卡

使用真实本地视频或现有可访问产物源，提供播放、暂停、时长、下载状态和对应任务入口。不能播放参考项目的示例视频，不能拿图片套播放器冒充视频生成。

全部镜头素材完成不等于整条短剧合成完成。此页面不新增整片导出/播放器。

### 4.7 画布交互

- 空白处拖动平移；缩放、缩放比例、适应画布、聚焦当前镜头可用。
- 文本框可选择、编辑、换行、中文输入、复制；滚动文本不误触整张画布缩放。
- 按钮和视频控件可点击，不触发画布拖动。
- 横向各列、纵向各行清晰对应；长提示词或竖图不覆盖下一行。
- 保持文本可读，不能为塞满五行自动缩成极小字号；允许纵向/横向浏览和聚焦。
- 节点状态刷新不重置用户视角或正在编辑的文本。
- 不要求新增自由连线、任意DAG编辑或无限节点类型。此处是生产流程的可视化，不是新工作流引擎。

## 5. 数据来源与真实接线

### 5.1 所有新创作正文来自豆包Chat

人物/道具/场景提示词、镜头首帧提示词、尾帧提示词、视频提示词和已有故事生成操作，全部调用当前项目的豆包普通Chat链路。

“所有提示词来自豆包”指用户用于创作的正文。现有固定请求模板、格式校验、引用编号替换可继续由程序完成，但不得由Codex、硬编码文本或本地拼接假装生成新的创作正文。

用户自己的剧本及手动修改仍保留，显示“用户输入/编辑”，不标作新豆包回复。旧提示词可以先展示，但须标为已有内容，不伪称本次重新生成。

**不改本轮提示词写法标准、不升级优化器、不人工润色生成结果。** 如果结果仍然简短或不好，原样回填让用户看，不能在开发会话中悄悄美化。解析/存储/回读故障影响页面真实使用时允许最小修复，这不属于提示词质量专项。

### 5.2 图片和视频来自豆包既有生成链

使用已确认参考图与当前最终文本，通过原P4的任务、上传、参数回读、观察和下载执行。图片回到对应卡片，视频回到对应播放器，无需手工下载再上传。

没有结果时显示未生成/生成中/失败，不填示例媒体。历史豆包产物可显示为已有素材；不要为装满画布擅自重新抽卡。

### 5.3 一份真实业务数据

以现有project/store/task/asset服务为来源，节点仅作展示与操作入口。不要另存一套互相脱节的画布剧本和final。

最小关联沿用既有字段：projectId、shotId或assetId、提示词用途、taskId/本次运行标识、当前采用文本、产物路径和状态。视角状态可单独保存；它不是执行状态。

豆包回复保存后更新对应节点；项目重开后能恢复。手改与异步回复有冲突时，新结果作为候选显示，不能静默覆盖用户输入；需要采用时在同一卡片操作即可，不做大型版本管理器。

节点卡片至少区分：待生成、排队/处理中、结果就绪、失败/待人工。详细的taskId和正文来源可折叠。生成完成、下载完成和文件校验不要混成没有依据的绿色勾。

页面切换、缩放、展开节点不得触发生成任务。现有账号Webview保持常驻，继续作为执行/登录/人工接管区域，不能因进入画布被卸载或重建。

### 5.4 执行动作

“生成全部提示词”只创建本轮文字任务，不暗中启动生图或视频。

“生成图片”“生成视频”“开始制作”沿用明确授权和现有任务链；基础素材未确认不跳过确认门槛。不要复制原项目默认的媒体失败自动重发策略。

旧按钮与新节点按钮共用服务，不能因双入口导致同一任务提交两次。
