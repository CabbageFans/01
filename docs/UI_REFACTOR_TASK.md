## 3. 采用的设计方向

采用“清爽、克制的Mac创作工作台”，而不是炫技的AI仪表盘或营销网站。

- 浅色中性背景、白色内容面板、清晰深灰正文；沿用紫色作为少量主操作强调色。
- 视频和图片预览区域可以使用深色底，避免整个外壳纯黑、内部豆包纯白的强烈割裂。
- 降低装饰密度，不做大渐变、发光边框、大面积毛玻璃、无意义统计卡片、欢迎横幅或宠物插画。
- 优先复用当前React、Ant Design、图标和样式体系，通过现有主题机制与少量设计token统一，不更换UI框架。
- 中文正文建议14px左右，次要文字不小于12px；页标题20～24px。采用系统中文字体，不下载字体包。
- 间距以8px尺度组织，圆角8～12px，边框轻，阴影只用于浮层。表单、按钮、标签、列表和抽屉统一规格。
- 导航和主要动作使用文字搭配图标；工具图标有提示和可访问名称，不用Emoji代替图标。
- 状态不能只靠颜色区分。长文本合理截断并可展开，数量、按钮和状态标签不得挤成竖排。

参考布局：左侧约190px导航，顶部约56px上下文栏，中心内容自适应，浏览器按需出现在右侧辅助区或独立工作区。具体尺寸随当前窗口验证，不机械套用。

Mac只保留一套实际有效的窗口控制，解决原生交通灯与应用内最小化/关闭按钮重复的问题；沿用已有关闭、隐藏、退出与Dock恢复行为，不擅自改变运行策略。

可使用本机已安装的Product Design等工具辅助截图分析、布局设计和视觉检查。使用前读取其实际技能说明，按已有工具能力执行，不把工具名当成已可调用的命令。

本轮设计目标和默认方向已经给定，不做长篇竞品研究和多轮无关风格探索。设计工具不可用时，沿用本方案在现有React工程实现，不以安装插件作为阻断。不要新建与原应用脱节的替代App，也不要停在静态HTML展示页。

使用清晰的“对话 / 图片 / 视频 / 音乐”模式切换。主体为提示词编辑与参考素材；配置区展示执行账号、真实可选参数以及必要说明。

### 5.3 创作工作台：萌宠短剧

采用四个阶段导航，中心显示当前阶段，保留项目名、绑定Studio项目、执行账号与保存状态：

保存抖音链接 → 复制手机豆包提取提示词 → 用户在手机操作 → 粘贴故事 → 保存故事。

本阶段提供两位主演基础参考图入口，确保生成方案前可准备参考素材。已有故事后，主操作为“生成制作方案”。Chat原文、格式问题和原任务正文补取放详情，不把开发JSON作为主界面。

**③ 制作准备**

无需展示大片“即将上线”区域；合成、整片导出、时间线等未实现按钮不放入主流程。

## 6. 状态与动作的不可混淆规则

以下是现有语义的呈现要求，不要求再建一套状态机。

| 情况 | 正确呈现/动作 |
|---|---|
| 草稿或仅已指派账号 | 待授权执行，不伪装成正在生成 |
| 已授权但依赖未满足 | 排队/依赖阻断，查看前置任务 |
| 提交前失败且确认未发送 | 按现有条件允许修正和重试 |
| 已被平台受理 | 继续观察原任务，不重新发送 |
| 提交状态不明 | 核对原会话/已有人工观察，不提供会重复提交的普通重试 |
| 生成完成、下载失败 | 显示结果已生成、下载失败；只重新下载 |
| 下载完成、文件尚未校验 | 显示已下载、校验待执行/未检查 |
| 文件校验通过、质量未判断 | 技术可用，人工质量未评，不自动显示优质/合格 |
| 人工拒收 | 保存质量结论，不自动消耗额度返工 |
| 短剧逐镜制作结束 | 素材制作完成，不代表已合成完整短剧 |

生成、下载、文件校验、人工质量用不同字段与紧凑标签展示，不能压缩成一个笼统绿色“全部完成”。不提供接口中不存在的动作。

## 7. 浏览器常驻是本轮关键技术边界

可以大幅改变浏览器的视觉位置，但不能破坏现有会话和正在运行的任务。

- 先识别`BrowserPanel`内哪些effect负责业务执行、轮询、恢复、事件和任务租约。不要把它当纯展示组件随路由卸载。
- 原账号Webview和partition保持稳定。页面切换、显示抽屉、展开/收起不得创建第二个同账号浏览器或重置会话。
- 采用一个稳定的运行时宿主。可以调整CSS布局、可见区域与展示状态，但不要在不同页面条件渲染两份BrowserPanel，或改变key导致重挂载。
- 收起策略沿用已有经过验证的后台保活、预热和前台交互租约。不要假设`display:none`、缩成零尺寸、随意移除DOM后执行仍正常。
- 需要可见控件执行或人工确认时，使用既有机制使正确账号页面可交互。不要因为当前路由是设置页就让上传、发送或产物观察失去上下文。
- 浏览器布局重排不得触发“首页导航”“新建对话”“重新上传”或“重新发送”。手动刷新也不能额外重启任务。
- 手动查看账号与执行账号占用继续遵守现有协调逻辑；不要为了自由切页绕开租约或取消保护。
- 若必须从原组件抽出少量宿主/展示边界，只做维持常驻所需的最小改动，不借机重写调度内核。

全宽账号页面与右侧辅助浏览器是同一宿主的两种展示方式，不是两个实际执行实例。

## 8. 自适应、交互细节与功能覆盖

以1440×900和用户截图尺寸附近为主要设计尺度，兼顾1280×800及应用当前允许的最小窗口。

宽屏时可用中心业务区＋约480～560px辅助浏览器；空间不足时改为覆盖式辅助区或全宽账号视图，不把表单和任务都挤到不可读。具体宽度以真实操作控件可用为准。

导航可折叠，主内容能独立滚动。避免整页横向滚动、重复滚动条、抽屉打开后主按钮消失、按钮文字换成竖排。数据表格确需横向滚动时仅在表格内发生。

保留中文输入、Cmd+C/V/A/Z、文件选择、CSV拖入和焦点恢复。拖拽标题栏区域不得覆盖表单和按钮。键盘能到达主要控件，焦点清楚，Esc关闭非强制浮层。

错误、加载、空状态、未登录、待确认、只读锁定、额度未知都要有真实文案。不要造数据填页面，也不要将未验证功能标为正式可用。

检查每个可见按钮都有真实处理函数、明确禁用原因或可追踪的已有跳转。不能留下只有console.log、假toast、空抽屉或静态样例的功能。

在设计文件中建立简短的“旧入口 → 新入口 → 原处理函数/组件”表，覆盖本指令第5节功能；重排可以，静默删功能不可以。

## 9. 实施顺序

**第一步：核对与短设计。** 启动现有应用，结合用户截图和代码确认布局问题；记录实际功能入口。先写短版页面布局、状态映射、浏览器常驻方案和功能去向，不重新做产品调研。

**第二步：全局外壳。** 先做主题、导航、上下文栏和稳定浏览器宿主，接入现有页面。保留工作流处理函数，再逐页改善，不先删除全部旧组件。

**第三步：创作核心。** 优先完成通用创作及萌宠短剧四阶段界面，处理动态镜头、提示词层级、编辑锁、模式及素材展示；所有已有操作必须接线。

**第四步：任务与素材。** 改造任务列表/详情、人工接管、批次、产物和下载视图，确保状态含义和动作不变。

**第五步：账号与设置。** 整理低频维护入口、额度来源和版本信息，完成旧功能映射核对。

**第六步：实际视觉回归。** 检查真实Electron窗口，逐页截图，修正遮挡、溢出、留白比例和信息密度。不是构建成功就结束。

可以使用现有Product Design工作流帮助设计和检查，但最终交付必须是当前仓库可运行的改造，不是仅一张设计图或外部原型。

## 10. 验证与交付

本轮是UI改造，不自行发送真实文字、生图、生视频或音乐任务，不消耗用户额度，不主动登录、清除登录、恢复备份或操作真实删除。普通导航与非写入的查看可验证；有副作用操作用本地隔离测试或由用户确认。

至少验证：

1. 主窗口能启动，1440×900、1280×800及当前最小可用尺寸不出现关键遮挡/裁切/竖排状态。
2. 六个主入口与通用创作、短剧四阶段均有正确页面和真实数据绑定。
3. P4方案锁定、最终提示词、动态角色/分镜、模式和四类结果状态正确展示。
4. 导航、辅助浏览器开合、抽屉与全宽视图切换不重挂载账号Webview、不改partition、不重发任务。可比较实例身份、事件记录和模拟运行；不要为证明这一点实际提交生成。
5. 执行账号与手动浏览账号、Studio项目与本地短剧绑定没有被视觉选择器误改。
6. 任务、批次与下载操作仍走原服务，下载重试不触发生成，人工质量判断不改变技术状态。
7. 构建、类型检查与改动相关测试真实通过。保留已有测试，必要时更新组件定位，不通过删除断言掩盖回归。
8. 功能入口映射无遗漏，音乐/Dola/首尾帧未验收能力没有被包装成已验证。

截图优先从真实Mac Electron窗口取得，并检查截图内容。浏览器中的开发预览只能证明对应前端布局，不能替代Electron会话常驻验收。工具不能观察真实窗口时，如实列出待用户验证项，不假称已经目测通过。

只提交简洁必要文档：
- OpenSpec当前UI变更文件。
- `docs/UI_REFACTOR_REPORT.md`：布局决定、旧新入口映射、改动摘要、测试/未测试项和启动方式。
- `artifacts/ui-refactor/`：本地前后对比与关键页面截图，遵守项目忽略规则；个人账号信息脱敏，不上传外部服务。

最终回复给出：
- 新页面结构和主要交互变化。
- 修改的关键文件及复用的服务。
- 哪些现有功能被搬到哪里，P5功能仍未加入。
- 浏览器常驻、任务状态和锁定机制的验证情况。
- 真实构建/测试/截图路径，以及仍待用户确认的项目。
- 准确的本机启动命令，启动应用供用户查看；工具不能持久维持进程时如实说明。

不要把UI验收通过写成所有豆包生成能力已验收。不要仅交付规划、静态原型或主题色修改。完成本轮改造后停止，不自动开发P5、不归档旧功能变更、不提交或推送Git。
