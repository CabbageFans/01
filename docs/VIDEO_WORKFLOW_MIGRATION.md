# 视频制作输入与项目事务兼容

实现以当前 `TaskService` / `TaskRepository` 为运行权威。`production` 只记录用户授权、当前待办和素材选择；`productionHistory` 保存旧步骤、输入与关联，不成为另一套任务运行状态。

## 输入边界与旧路径

- 正式调用仍通过 `compilePrompt` / `compileMaterialPrompt`。`petstoryPromptQuality.ts` 和 `petstoryMaterials.ts` 保留资格包装；引用映射移入 `petstoryPromptReferences.ts`，素材事实移入 `petstoryMaterialFacts.ts`。`eligibility`、`validation`、连续参考与文字上下文直接消费纯事实，去掉资格与编译之间的运行时导入环。
- `videoInputCompiler.ts` 在创建步骤时保存 `VideoInputSnapshot`，包含输入版本、镜头/步骤/账号、逻辑模式、参数、原文、逐字对白、编译文本及有序素材摘要。`Task.videoInputSnapshot` 是下一次运行输入；启动时复制到 `Task.runtime.input.videoInputSnapshot`，运行中不改写。制作步骤保留同份来源供追溯。
- 明确授权把未发送的首尾帧改成两参考图时，原运行完整保留在授权历史，新输入版本经 `revisePetStoryVideoInput` 固定到原 hold 任务，新 run 消费新版本。普通页面编号映射使用专用 `bindPetStoryPageInput`，不会修改来源快照。

## 项目与任务半写入

`petstoryTaskTransaction.ts` 是制作和后台正文的共用协调器。项目 `taskIntents` 固定 operation/step/job 身份、输入及原账号后才创建 hold 任务；媒体步骤和正文 job 的最终关联随项目一次原子保存。`TaskService.create` 按业务绑定幂等，补写不能形成第二条任务。

|中断位置|恢复|
|---|---|
|意图尚未保存|没有任务或平台操作，显式重试可建立同一待办|
|意图已存、任务创建失败|显式继续消费原意图，保留原 operation/step/job 身份|
|任务已存、账号绑定失败|复用原任务，补完原账号绑定|
|任务已存、项目回填失败|打开项目只修复唯一已有任务的关联，零派发；显式继续再启动|
|页面绑定已存、任务正文更新失败|同 run 相同绑定可重入补写；重启后保存旧绑定历史，回到原 task 的页面准备阶段|
|旧 preparing 无 taskId、有唯一匹配任务|按原 project/step/账号/输入精确回填|
|旧 preparing 无完整意图且无匹配任务|给出明确原因，可结束本次制作后按当前输入生成，不凭猜测补随机任务|
|旧 step/run 不一致或多个匹配任务|保留记录并拒绝混用，可结束本次制作；不自动改认新 run|

读入兼容可重复执行。没有新字段的旧项目继续使用历史适配，不批量清空 production、任务或媒体，不删除原文件。

## 暂停、结束、后台镜头

- 暂停/结束先撤销本地授权并取消原下载等待，网络、哈希和解码不占用项目短写队列。长操作完成后重新读取项目，仅按原 step/task/run 回填。
- 任务详情暂停、批量暂停和本机停止命令都保存原 run 的 `paused`（正式结束为 `cancelled`），并把受理/人工观察租约结束为 `manual_review`；提交时间、受理事实、输入快照和原会话保留。显式暂停不会因异常收束或组件重挂载自动恢复观察。保存失败只撤本地执行权并提示重试保存，不构造已暂停快照。
- “结束本次制作”把当前制作保存为 `ended` 历史并解除活动槽，原任务和已提交平台请求保留。结束不声称远端生成已经取消。迟到媒体只能补原历史，不能改新制作或新选中视频。
- 切换项目通过 `detachProduction` 保留当前视频执行权；完成该镜的观察、下载和入库后，单镜授权完成，批次暂停后续镜头。切换本身不暂停 Task 或改变 run，返回后明确继续可调度下一镜。
- 一次制作推进 IPC 失败会尝试持久暂停。暂停写入失败时明确显示“本地已停止、记录未保存”，不伪造成功快照。
- 下载、媒体工具、入库失败分别显示“重试下载”“重新校验”“重试入库”，均只接续已完成原任务的收取。画布媒体读取失败提供“重新读取”；已有视频保留“生成新版本”。

## 诊断与验证

现有诊断导出追加 `PetStoryProjects.diagnostics()`。按 project/shot/step/task/run 关联输入摘要、引用摘要、页面绑定、重发历史、下载/校验错误和本地资产来源；不输出原文、创作正文、凭据、素材绝对路径或平台内部地址。

行为验证位于 `petstoryTaskTransaction.test.ts`（四个关键写点）、`petstoryProduction.test.ts`（模式、快照、页面绑定、重启、后台镜头、结束后迟到媒体）、`petstoryProductionRace.test.ts`、`petstoryProjectSwitchStore.test.ts`、`petstoryDiagnostics.test.ts`，并保留原图片服务、候选采用及正文创作回归。已替换的旧断言包括永久阻断半写入恢复、相同页面绑定一律拒绝、切项目必须停止视频、播放必须依赖当前 Task，以及用正式命令任意回退完成终态的夹具。替代断言核对原任务唯一性、零重复派发、原成果保留和服务端状态约束。

完整门禁与真实账号闭环结果见 [视频重构验收](architecture/VIDEO_WORKFLOW_REFACTOR.md)。本文件不把离线测试当成真实平台成功证据。

## 最终收口

`Task.status=done` 明确表示平台产物已可靠识别；同一 `Task.runtime.localMedia` 是下载、文件校验、入库的唯一阶段事实。所有本地回执经 `TaskService.updateLocalMedia` 校验原 run/artifact/inputVersion 和 revision，暂停、结束及迟到写入不相互覆盖。制作 step 的文件关联是项目目录投影，旧 step.failure 仅适配历史无此字段的记录。library checkpoint 保存计划 assetId 与 mediaInfo，项目写入失败后复用同一库文件并补关联，不重新下载或解码。阶段回执随 `taskSnapshots` 进入版本化 Store。

统一 `videoWorkflowActions` 为画布、制作恢复和任务中心给出准备、原结果选择/验证/地址刷新、下载、重新校验、入库、新版本与结束动作。已暂停制作的原结果检查变成 done 后，advance 只收取该原任务，不授权下一个镜头。

画布当前活动视频节点在节点按钮区直接提供“暂停后续制作”和“结束本次制作”，复用正式 Store 命令；暂停后仍可明确结束。入口按当前制作的待办 video step、镜头、task/run 归属显示，点击前再次核对原制作身份。独立镜头、已完成节点和历史节点不会显示用于结束其他制作的按钮，生成入口被锁定也不阻止用户停止本次等待。

正式结束视频等待会以原 run 保存 Task.cancelled，保留提交、输入、原会话与受理证据，并释放本地账号槽；平台并未被取消。图片停止后新增“结束本次图片等待”：对已暂停／失败的本地等待明确结束，移除活动图片制作绑定，把原制作作为 `ended` 记录归档。原 Task、run、豆包对话、已保存媒体和图片候选均保留；结束可重入，不创建任务或再次发送。继续原图片与结束图片等待是两个动作，结束后才解除该等待保护的同镜视频参数锁。

图片等待对视频设置的保护按 `shotId` 划定范围：同镜已保存制作快照的暂停等待继续保留输入锁，用户需先结束该等待，再修改本镜模式或时长；其他镜头及不属于该镜头的基础素材历史暂停不会阻断它。前端画布和后端 `savePlan` 使用相同范围，当前视频主制作原有的输入保护继续生效。

真实现场暴露了旧 `imageProductions` 的兼容问题：已完成首帧等图片制作保存了当时的 `auto` 等模式，当前草稿改用 `first_frame` 时，旧校验错误地要求两者相等。独立图片制作和归档制作现按自身冻结的 `requestedMode`／`resolvedMode`、镜头与素材归属校验，不拿当前视频草稿模式验证历史。保存新模式、重开项目均不改写任何旧 `run.shots`，非法历史模式和跨镜素材错绑仍拒绝保存。相关回归通过公开项目／制作服务验证冻结历史、结束尾帧后保存首帧模式及重开结果。

2026-11-10 已完成一次完整门禁：252 个测试文件、4807 项测试通过；最终交付元数据复核以[视频重构验收](architecture/VIDEO_WORKFLOW_REFACTOR.md)为准。真实平台现场原请求 `aeff` 只返回可复制提示词，未识别到视频卡或取得视频文件，尚未完成真实平台生成至本地播放闭环。用户明确选择“先不重发，只保留原结果”，本次保留原请求、不创建关联重发任务；离线可信原生事件和本地媒体测试不替代这项实机结果。
