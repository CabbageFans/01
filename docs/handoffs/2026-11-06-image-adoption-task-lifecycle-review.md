# 图片采用阻断与任务生命周期审查（2026-11-06）

## 现场问题

雨后村道原任务已经完成并保存三张可解码候选；点击采用第三张仍提示“当前图片或其实际引用仍有未结束任务”。阻断来自同素材的旧图片操作：旧 Task 在发送前暂停，没有提交时间、受理证据、产物或执行锁；后续显式请求已替代它，但旧 `failed` 操作和 `paused` 制作记录仍被采用门当作当前占用。

历史记录没有丢失，也不需要删除或伪造任务完成状态。错误在于创建、恢复、采用分别维护了不同的占用判断。

## 审查发现与修正

| 发现 | 原因 | 修正 |
| --- | --- | --- |
| P1 旧失败操作永久锁住新成果 | 创建允许替代，恢复拒绝旧操作，采用却继续扫描旧暂停制作 | 共享当前操作与历史操作判定；被后续同目标请求取代的完成／失败记录退出占用 |
| P1 已完成步骤仍锁引用图片 | 检查所有步骤附件，没有排除完成步骤 | 只检查未完成步骤的真实附件引用 |
| P2 遗留暂停标记与完成步骤矛盾 | 把制作调度状态当成保存结果的唯一依据 | 有明确步骤时按步骤是否完成判定；空步骤未知状态继续保护 |
| P2 旧式独立图片被当成全项目批次 | 旧 `production.imageOperationId` 先经过全局锁再经过目标锁 | 旧式与独立槽图片复用同一策略；完整批次继续保留原全局输入保护 |
| P2 成功采用后仍显示旧目标错误 | 只清全局错误，保留优先显示的目标错误 | 成功回读确认选中图片后，只清同项目、同目标、同请求的原错误 |
| P2 迟到采用响应可能覆盖新项目 | 通用 `accept` 允许接收不同项目，采用响应缺少入口归属校验 | 在采用调用接受响应之前检查项目／账号／工作区归属，后来请求及同文案新错误继续保留 |

## 状态责任与维护约束

- `TaskService` 管平台任务、运行身份、提交意图与受理结果。暂停并不等于从未提交，不能通过删除任务或改为完成解除占用。
- Production 步骤管具体输入、产物收取和保存完成。平台 Task 完成与项目候选保存完成是两个阶段。
- 图片 Operation 管用户一次图片请求的准备、生成与保存进度；历史操作继续保存原任务、反馈、基图和运行来源。
- Renderer 错误属于具体目标及请求，不能拿一条旧错误推断当前任务状态，也不能清掉等待期间的新错误。

`main/utils/petstoryImageLifecycle.ts` 集中提供目标比较、独立／旧式制作定位、当前操作、未结束工作和实际引用占用规则。创建、恢复和采用复用这些规则；独立图片与完整制作批次仍分别按其输入范围保护。旧非终态操作即使存在后来记录，也继续保护，避免异常历史数据掩盖真正仍在运行的任务。

新增回归通过公开项目与 TaskService 服务链验证“旧失败 → 明确新请求 → 新图完成 → 正式采用”，检查原 Task/run/反馈/历史/基图不变；范围回归覆盖新旧存储、已完成引用、真实未完成引用、旧非终态及空计划保护；采用回读回归覆盖失败、项目漂移、请求漂移、同文案新错误与批量定向清理。
