# 已有图片的原任务恢复修复（2026-11-06）

## 问题证据

实际只读诊断记录显示，原用户消息的完整提示词已经精确匹配；同一会话新增空用户消息后，恢复仍返回 `user_ambiguous`，并在一分钟后超时。失败发生在原请求身份预检，尚未进入图卡读取和候选保存。

另用真实序列化读取器和合成 provider DTO 复现：`content_blocks_v2.content_obj` 已声明完成的三张原图并与图卡渲染源对应，旧读取器仍返回 `imageArtifactPending=true`、空原图列表。

## 根因与修复

1. 恢复误复用发送回执的“整个会话只能有一个用户请求”规则。新增专门的已提交图片只读定位：完整原请求与服务器消息 ID 决定归属，后发用户消息默认截止原回复区间。
2. 旧任务缺少耐久收据时，已有会话地址和缺地址两条恢复路径均补存原服务器消息 ID；后续恢复可以复用，输入、原运行和原提交时间保留。
3. 完整历史的结构性歧义原本只会反复重读到超时。恢复在连续两次完整且相同的歧义后明确结束；尚未加载的历史仍允许等待，发送前默认行为不变。
4. 图卡读取同时支持新版 `content_blocks_v2.content_obj` 和旧版 `content.creation_block`，继续要求本消息真实图片卡与平台显式原图字段关联，不以缩略图或整页最后一张图代替。
5. 真实会话由“原要求 → 文字方案 → 纯执行生成短指令 → 三张图片”组成。旧读取器在短指令处一律截止，导致身份核对通过后仍等不到图。现在仅在完整历史、唯一服务器消息 ID、原回复无图卡／产物、首个后续指令只要求执行原方案且无附件、图片回复有明确父链时，只读接回该既有图片回复；其后新用户消息仍截止，已有原图优先，不发送任何新指令。
6. 服务器消息 ID 与原全文一致时，不再以可能共享或重新挂载后变化的 union 分组 ID 否定原身份。无服务器 ID 时，分组 ID 不能消解重复全文歧义。

## 回归覆盖

- 真实 BrowserPanel 恢复闭包：缺收据、多轮会话、后发空消息、新草稿；分别覆盖已有和缺少原会话地址。
- 唯一全文、重复同文、原服务器 ID、错误 ID、全文变化、账号／运行／会话漂移。
- 真实序列化 DOM/provider 读取：三张候选完整收取，新旧 v2 图片结构，后续图片不能串入原任务。
- 原要求先取得方案、已有纯执行短指令再取得三张图片：真实 BrowserPanel 闭包联动产物读取验证；修改、数量、参数、附件、未知父链、重复 ID 均不能借此续接。
- 完整稳定歧义快速结束，不完整历史继续等待，取消优先，不重新发送。

此前测试主要覆盖单用户请求或已有耐久收据的恢复，缺少“旧任务无收据、多轮会话”组合，并把文字方案与实际图片错误简化成同一条回复；产物测试的合成模型也未覆盖新版 v2 字段。这些缺口使单测通过不足以证明现场恢复。本次新增用例均先在修复前复现失败，再验证修复。
