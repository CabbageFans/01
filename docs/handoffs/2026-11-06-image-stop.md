# 图片任务停止与手动肯定回复收图

## 用户现象与原因

豆包收到图片请求后可能先询问是否生图。用户在原对话回复“要”并得到图片后，工具仍然等待。原读取器仅接受明确生图指令，未识别与原助手明确生图询问绑定的简短肯定回复；原图片进度也缺少立即停止入口。

实机中的具体问句是“你现在是要我直接调用生图生成这张图吗？”。先用该真实句式复现 `image_pending`，再补齐有限的询问语法及正、负回归。只测试“要不要为你生成”之类简化样例不足以覆盖这个现场。

## 行为与边界

- 图片卡片、候选预览和图片修改弹窗在准备、生成等待与保存期间提供“停止”，即使生成入口已禁用也可使用。
- 停止先撤销本次图片操作及在途启动的执行权，打断 AutomationEngine 和 BrowserPanel 独立的只读观察，再通过正式接口保存原任务的 paused / hold 状态。停止不排在长时间图片处理队列之后。
- 原 taskId、runId、submittedAt、提示词、会话归属和已有图片保留。继续入口复用原任务；工具不自动回复“要”、不自动重发、不点击豆包平台的停止按钮。
- begin / prepare / repair / bind / resume 的迟到回执不能恢复执行。尚未返回的新建 hold 任务在回执到达后暂停，不再分派。保存恰好完成时保留 done 任务及候选，不将完成结果降回暂停。
- 暂停保存失败显示真实原因并允许再次停止；切换项目、目标或停止后，旧界面回调不能覆盖新预览。
- 短肯定回复仅在原助手最后的有效回复明确询问是否生成图片时接回；仍要求完整历史、唯一服务器消息 ID、首个后续用户轮次、无附件和明确回复父链。原轮次已形成图片时优先使用原图片。

## 维护入口

- `src/components/PetStoryImageReview.tsx`：停止操作与异步界面回调边界。
- `src/store/usePetStoryStore.ts`：单图片流程的授权、停止、暂停确认与迟到回执处置。
- `src/utils/imageArtifactReadback.ts`：原请求与用户肯定续接的只读归属判断。
- `tests/unit/petstoryImageStopStore.test.ts`、`petstoryImageStop.dom.test.tsx`：在途 IPC、观察取消、保存并发、失败与界面验收。

## 真实原任务验收

在原长木棍任务上执行“继续本次任务 → 停止”，正式任务回读为 `paused / hold`，制作状态为暂停，运行 ID、原提交时间、尝试次数和输入保持一致，图片流程占用释放。再次继续后，原对话现有图片只读恢复为 1 个本地已解码候选，任务为 `done`、操作为 `complete`。任务总数始终为 78，未新增平台请求，未代用户采用图片。

完整 `pnpm run validate` 通过：206 个测试文件、4276 项测试，类型、Lint、工程与契约检查及两端构建通过。末轮旧运行身份隔离补丁另外通过全部 Store 相关回归及类型和构建复验；停止专项为 17 项 Store 回归和 13 项 DOM 回归。实机最终停在长木棍候选预览，图片可读取，“满意，采用图片”可用，未自动采用。
