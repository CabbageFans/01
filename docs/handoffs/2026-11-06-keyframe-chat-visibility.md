# 打开豆包 Chat 时关键帧生成被暂停

## 原因与修正

“豆包对话正在打开，请收起后继续生成；本次尚未发送”来自应用的页面占用保护，并非豆包平台拒绝。基础素材图片及其准备文字已经使用独立任务页，但镜头首尾帧没有 `materialId`，因此仍被路由到账号自由聊天页；Chat 面板可见时，旧的共享页面保护会在执行前暂停这些任务。

正式图片操作及其准备文字现在根据原账号、项目、图片操作和步骤／文字请求绑定获得独立任务页，不再要求素材 ID。关键帧使用自己的页面执行，右侧 Chat 的展开或收起不再阻止本次图片操作。独立任务页仍使用原账号 partition，不借用或清空账号自由聊天页。

页面隔离与任务调度范围分开判断。素材执行槽、关键帧的账号互斥和全应用一次一个图片流程的限制保持原规则；没有扩大图片并发或自动重发权限。共享页面的草稿与交互保护、真实输入区就绪、账号可用性、提交意图持久化、单次发送和产物回读检查继续生效。

## 恢复兼容

旧关键帧如果已经记录提交、缺少可验证的原会话定位，且当前运行没有独立任务页，继续保留账号原现场，不新建空白任务页。新独立任务页在记录提交意图后，即使定位尚未出现，也保持原账号、原 taskId 和原 runId 对应的同一页面。已有原会话定位的关键帧可以在独立任务页恢复原对话。

## 验证边界

离线回归覆盖 Chat 初始展开、准备途中展开、首尾帧的图片任务与后台文字准备、独立页就绪和恢复、旧共享现场保留、草稿保护、单次提交及原有单图片调度。验证不向豆包提交新的生成请求，真实平台生成仍需人工验收。

`pnpm run validate` 通过：210 个测试文件、4338 项测试；类型检查、工程规则、契约检查及两端构建通过。ESLint 为 0 错误、148 条警告，在现有门禁阈值内；构建保留大分块提示。`git diff --check` 通过。
