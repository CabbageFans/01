# 停止图片任务后允许上传和采用

## 根因

细树枝原任务已保存为 `paused / hold`，图片操作为 `failed`，其独立制作记录为 `paused`。原步骤保留 `bound` 和原任务、运行、输入及提交证据，这是正确的恢复信息；但媒体编辑检查把这些“仍可继续的工作”同时当作输入锁，导致停止后上传仍报“当前图片或其实际引用仍有未结束任务”。

## 修正边界

- `imageOperationHasPendingWork` 继续用于原任务恢复和防止重复创建，不因上传而伪造完成状态。
- `imageOperationHoldsInputLock` 单独判断媒体编辑占用；已暂停的制作释放媒体编辑锁。运行中的本目标与真实附件引用继续受保护。
- 图片上传、预览选图、明确采用使用具体目标检查；剧本和正文等非媒体编辑仍保留原未完成约束。
- 上传仅新增候选；明确采用才改变当前图片。原任务、运行、提交、历史图片和制作记录保留，不自动发送或重发。
- 上传与采用复用同一项目／账号、图片请求和错误版本保护，仅在本目标的新候选确已返回时清理旧提示。新上传图预览不继承旧生图任务的暂停错误；卡片继续保留原任务入口。
- 放开暂停期间换图后，恢复入口在重试／重置输入前核对原制作依据，防止把旧授权用于已改变的实际引用。

## 现场复现

在当前项目的隔离副本上使用真实 `PetStoryProjects` 调用复现了相同阻塞。修正后上传、文件复制、图片解码、候选预览资格及明确采用均成功，原停止任务和制作历史未改变；原项目文件摘要保持一致。测试图片仅用于隔离副本，未代用户上传或采用到原项目。

主实例已正常退出并使用相同 `mac-dev` profile 重启，打开原项目，细树枝上传入口可用。TaskService 复核任务总数仍为 79；原任务仍为 `paused / hold`，原 run、submittedAt 和 input 与修复前一致，无新增生成请求。

最终 `pnpm run validate` 通过：207 个测试文件、4303 项测试，类型、Lint、工程／契约检查和两端构建通过。新增覆盖真实停止后的上传／采用、活跃引用仍保护、未采用候选不改变恢复依据、已换实际引用时零重试、上传失败／取消／迟到回读及旧错误隔离。另修复管理界面测试销毁前未等待 AntD 提示根清理的问题，未改变产品逻辑或屏蔽异常。
