# 停止图片后的历史观察占用修复（2026-11-06）

## 现场与根因

制作关键帧时，镜头提示词准备提示“该账号仍绑定生成确认或人工提交观察会话；请先完成只读回读或人工取消”。正式控制接口确认账号登录正常且不忙，新的文字任务尚未提交。

真正的占用来自此前停止的“细树枝”图片任务：状态为 `paused / hold`、错误码为 `cancelled`，没有执行锁，原观察租约早已过期；其 `acceptanceObservation.outcome` 仍为 `observing`。这个字段保留原受理证据，不能删除，但 Renderer 的显式启动和自动队列两处都只排除了 `cancelled` 状态，把已经停止的图片历史当作持续账号占用。

## 修正边界

- 两处调度检查共用 `hasPendingAccountObservation`；已完成、已取消任务，以及明确停止的图片任务（图片执行类型、`paused / hold`、`cancelled` 错误码）不再仅因历史观察标记占用账号。
- 不修改原任务、输入、运行 ID、提交时间、受理证据、对话定位及历史产物；原任务普通 retry 仍拒绝重新发送。
- 真正执行、生成、只读观察、等待确认与等待验证的任务仍阻塞；有效执行锁、执行槽及引擎预约继续检查。
- 其他提交不明的暂停／失败任务仍沿原核对规则；没有扩大重发或会话接管权限。新的 hold 任务仍需要明确启动授权。

## 验证

新增 `stoppedObservationScheduling.test.ts`，通过真实 Store → TaskService 链复现现场，首次运行复现三项失败：显式开始、已授权队列接续、完成历史残留观察。修复后 13 项回归通过，覆盖原记录不变、禁止原任务重发、hold 不自动授权、有效锁以及五种真实活动状态仍受保护。

`pnpm run validate` 全部通过：208 个测试文件、4316 项测试，类型检查、工程与契约检查、两端构建通过；ESLint 为 0 错误、148 条警告。独立只读审查未发现安全回归。

实机重新打开原项目。开发热更新时原文字任务因项目尚未打开而在发送前安全暂停；确认没有提交或回复证据后，通过带鉴权的正式本机控制接口恢复同一 taskId，重新绑定本次运行。该任务随后完成，正文回读存在，项目 job 已正式采用（`applied`），镜头 1 首帧提示词已在画布显示，原账号占用报错消失。

恢复前后“细树枝”停止任务的完整记录摘要一致，仍为 `paused / hold` 且无执行锁；任务总数仍为 80，没有新增平台图片生成或重发旧图片。其他五项镜头提示词保持待用户继续生成。本次未创建版本 Tag 或 Release。
