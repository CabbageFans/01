## 建议评审路径

1. 从输入剧本开始，检查分析、候选方案、采用与确认的交接。
2. 进入基础素材，查看候选图片并选择一张；上传本地图片时检查目标、用途、预览和采用。查看替换状态时，旧采用图应保持到确认替换。
3. 在关键帧／视频阶段检查完整画布、镜头定位、全文编辑、缺素材定位、首尾帧与视频对应关系。
4. 从“在豆包中调整”打开对象关联面板，选择具体回复，预览目标与内容后采用。检查对话中和未选回复状态。
5. 在任务中心检查结果不明与下载失败；在成果中检查各维度独立呈现。
6. 浏览管理页面，比较字体、间距、按钮、主色与低频操作层级。

## Product Design 的实际使用

本轮使用 Product Design 工作流：入口分流 → 用户上下文预检 → 上下文回放 → 当前源码、已有设计和画布证据审查 → 当前 Electron 只读截图 → 基于用户已确认的现有 ai_story 画布视觉资产进入 image-to-code → 独立完整产品原型 → 浏览器评审。

用户本次明确要求完整产品设计，因而没有把工作停在三张首页选项；没有采用历史未选中的概念方案。保留的画布来源是已有工程和用户指定文件，而不是重新发明一套生产画布。旧报告中提到的 `docs/PetStory_UI_Design_Concept.html` 和若干历史设计产物在当前副本缺失，未当作已读取或已确认的证据。

## 原型和素材的准确边界

- 原型只模拟前端交互，数据在浏览器内用于展示，不连接正式 IPC、任务服务、数据库或平台 API，不向豆包或其他模型发请求。刷新可恢复样例状态。
- 点击“分析”“生成图片”“生成视频”“应用回复”等只演示页面与确认层，不代表真正执行或保存到用户项目。原型提示中的完成反馈是交互样例。
- 图片从现有 `docs/prompt-quality/frames/` 历史抽帧复制，只用于检查图片容纳、缩略图、预览和节点布局。它们并非本次示例故事新生成的素材，画面内容不证明故事、角色或镜头关系正确。
- 提示词正文是用于查看／编辑／采用版式的编辑占位样例，未被验证为豆包真实输出，不能导入正式生产充当创作正文。
- 豆包对话、助手回复、视频状态、任务、下载、文件校验、账号和质量结论都是界面样例。没有新增真实 Chat、图片、视频或完整成片。
- 上述说明集中放在独立评审入口与本文中，产品页面本身采用面向用户的任务文案。

## 本轮验证与停止点

对当前正式应用仅做源码读取和一张任务中心只读截图，不能称为完整实机走查。本轮在浏览器对独立原型按 1440 × 900 和 1280 × 800 检查页面与交互，具体已留存证据以 `evidence/` 中的文件和评审入口列出的记录为准；这些检查不等于 Electron 生产验收。

没有运行主工程产品测试或完整 `validate`；没有执行真实剧本到媒体的生产流程。原型构建和浏览器检查即使通过，也不能证明未实现的图片采用门、自由 Chat 回复应用或人工发送已接通。

下一步仅是用户评审并明确批准最终视觉。收到明确批准后，才接续既有 OpenSpec 进行实现、适用测试和真实界面验收。当前不进入开发，不提交或发布。
