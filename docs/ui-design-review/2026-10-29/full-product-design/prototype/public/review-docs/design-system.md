以下是批准后实现与验收的访问性目标，不是已取得完整符合性结论：正文对比 4.5:1，控件与焦点 3:1；不可用原因使用可读正文；焦点清晰可见；Tab／Enter／Space 可操作；Esc 关闭浮层并回到触发项；弹窗锁定焦点。原型中已建焦点循环与 Esc 行为，可按浏览器评审记录核验，其余仍需正式应用逐项测试。

图片提供用途与对象 alt；文件格式、尺寸／解码错误就地表达。状态通过文字与图形共同呈现；状态更新不抢焦点。画布缩放、适应、镜头定位提供按钮入口，拖拽不是唯一方式。减弱动态时禁用平滑滚动和长过渡。上传键盘操作、真实文件读取、读屏播报、所有状态的对比度与焦点恢复仍属于批准后的正式验收范围。

## 5. 保留的画布资产

当前实现基线：内容宽 1744；故事栏宽 340；镜头行四列 360／280／360／280，间距 28；左侧标题基准列 352。设计保留这些主要对应关系，不重新设计成普通卡片列表、表单或向导。

- 左侧故事与基础素材常驻画布；右侧每个镜头一行，镜头数量由方案决定。
- 横向顺序：**分镜／生图提示词 → 首帧／可选尾帧 → 视频提示词／运镜 → 镜头视频**。
- 浅网格、白节点、行连接、列标题、平移、缩放、镜头定位、完整提示词编辑全部保留。首尾帧在同一关键帧节点垂直排布，不生成新的平行画布。
- 阶段 4 聚焦当前镜头的关键帧列，阶段 5 聚焦视频列；仅通过定位、选中边框和任务操作改变焦点，不隐藏故事栏或其他列。
- 工具栏：当前项目名称、已保存状态；右侧“定位镜头”、适应、缩小／百分比／放大。制作设置与批量请求进更多。用低饱和选中边框标记当前镜头行。
- 节点当前图区只放已采用图片。候选到来显示小型“2 张待选择”入口；不可用候选缩略图伪装正式回填。空位可显示轮廓占位和“尚未采用图片”。
- 全文查看／编辑在独立弹窗中完成，保存只作用于这一对象；关闭回原画布。手改未保存时提示保存／保留草稿／放弃，不因候选到来覆盖内容。

## 7. 必须设计出的交互状态

1. **正常制作**：当前采用正文、已采用图片和真实下一步可见；浏览或切阶段不发送请求。
2. **图片待确认**：完整候选图＋候选序号＋用途（例如“人物：噜噜”）＋来源／文件有效性；“采用这张”为主动作。“稍后处理”关闭不采用。
3. **上传图片**：从对象节点点击上传，选择文件后同一确认层预览；用途由入口锁定。无内部 ID 输入；文件无效就地报错，不替换当前图片。
4. **豆包对话中**：面板标题持续显示目标；用户自由聊天期间暂停后续自动任务注入，不覆盖草稿、不切会话；收起面板不丢上下文。
5. **回复待采用**：用户选定具体回复后，预览完整内容与唯一目标；确认前当前正文不变；“确认采用”后才写入对象。
6. **缺少前置素材**：例如“镜头 3 还缺少已确认的首帧”；主恢复入口“去确认首帧”；保留已完成视频和历史，不默认批量重做。
7. **任务等待**：排队、等待登录、等待验证、等待平台结果分开；可见当前动作；不通过导航或刷新重发。
8. **失败恢复**：区分尚未发送、发送结果不明、下载失败、文件损坏、候选不匹配；操作名称明确，不统一叫“重试”。

## 8. 采用、历史与影响

人物、道具、场景、首帧、尾帧共用一个确认组件。记录分为“当前采用”“待选择候选”“历史图片”，界面也必须分开。候选下载保存不等于采用。原型展示逐张选择、候选关闭后保留和替换历史。批量确认已检查图片是正式实现要求，原型未建批量检查／采用；实现时默认勾选数为 0。

确认替换时显示旧图／新图与用途。旧图保持在历史；新候选未确认时旧采用图保持在节点与下游引用中。替换基础图后仅标记相关镜头“素材已更新，请复核”，保留现有成果，不删除、不自动生成。已确认图片跨镜头复用时展示来源和用途，不重复要求确认同一图。

自由 Chat 不能自动取最后一条助手消息。回复列表必须展示可辨认的预览、时间／顺序、选择态与全文；只选择助手正文。选中后“应用到当前创作”打开目标确认；出现歧义时停下并要求重新选具体回复，不能猜归属。迟到回复进入历史候选，不能覆盖新版本或手改正文。需要整理时可让豆包整理后重新选择，用户不写 JSON。

## 9. 当前实现与设计目标的边界

源码 `BrowserPanel.tsx` 在持久化发送意图后调用 `submitPromptWithNativeClick`，当前普通 Chat 是**工具自动发送**。不能把 `manual_submission_observing` 状态名当作普通 Chat 已支持人工发送的证据。当前设计的普通 Chat 请求提示是“将向豆包发送这次请求”，进行中为“豆包正在回复”。

若后续确实实现人工发送，替换为“内容和附件已准备好，请在豆包中点击发送”，发送后自动读取；不能加“我已发送／开始监听／确认收取”三个额外按钮。此分支必须经过真实页面验证后才能成为可交付能力。原型可演示具体回复选择、目标确认、局部回填和草稿保护；真实 DOM 回复识别、来源凭证、会话保护与自动请求暂停仍需批准后接线，不能因原型可点即宣称生产能力完成。

本轮不增加 P5 合成、配音、字幕编辑、自动发布、其他模型 API、第二执行器或第二项目数据库。所有正式创作正文来自豆包普通 Chat 的真实回复；原型文字和画面仅为设计样例，统一在外部 README／评审说明披露未连接平台，不在产品标题或每个节点加入样例标签。Dola 继续标注实验、未完成真实端到端验收。

原型中的批量操作、任务、账号、下载、诊断和备份是交互呈现；没有实际调用豆包、下载、文件哈希校验或写入产品数据。示意的状态流与确认动作不等于后台能力完成。真实图片解码、下载／校验凭证、结果归属、批量已检查采用及平台回复来源是后续实现和实机验收项。

## 10. 设计冻结与后续验收

用户明确批准本目录的最终原型和规范后，冻结布局、色彩、字体、间距、按钮规格、导航、文案与信息层级。实现遇到限制先记录差异，不自行换设计。批准后才进入开发与测试；最终要在真实界面走通六阶段，检查 1440×900 与 1280×800、图片生成／上传待确认、回复选择、缺项、等待和失败恢复。静态原型、函数调用、截图均不能替代生产流程实机验收。
