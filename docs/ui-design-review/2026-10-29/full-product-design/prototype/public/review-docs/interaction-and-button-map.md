# 短剧工作室 · 关键交互与按钮清单

状态：**设计评审稿，待最终视觉批准；尚未应用到正式产品。** 本文与 `design-system.md` 配套。常规按钮高 36 px／左右 14 px／字号 13；紧凑按钮高 30 px／左右 10 px／字号 12；画布节点按钮原始高 32 px。同一行同高，每个区域只突出一个主动作。列表中的“移入更多”是保留能力、降低视觉优先级；“取消”只针对通用创作和重复入口。

## 1. 六阶段操作链

| 场景 | 用户操作 | 工作室反馈与下一步 | 不得发生 |
| --- | --- | --- | --- |
| 输入完整剧本 | “分析剧本” | 先保存；成功后发送普通 Chat；展示本次故事理解、素材清单和动态分镜候选 | 保存失败仍发送；抖音链接成为必经步骤 |
| 原文尚未保存 | 离开或切项目 | 保留草稿；给出保存、保留草稿、放弃的明确选择 | 丢输入、候选到达清空草稿 |
| 方案候选到达 | 查看、编辑或在豆包调整 | “采用此方案”更新当前方案；随后“确认方案并准备素材”固定制作依据 | 收到即确认；确认即启动生图／视频 |
| 基础图缺失 | 生成图片或上传图片 | 下载／文件校验后进入同一待确认区，显示用途与目标 | 上传即正式选中；首张返回即正式回填 |
| 图片待确认 | 打开候选、切换大图、“采用这张” | 只有确认后更新正式节点；有旧图时显示替换对照与影响镜头 | 默认全选；候选覆盖当前采用图 |
| 关键帧制作 | 在完整画布定位镜头 | 提示词先看／编辑，图片生成后仍进待确认层；可选尾帧按实际模式显示 | 画布变为表单；未采用图作为视频引用 |
| 视频制作 | 核对模式／时长／参考图、“生成视频”→“开始生成此镜” | 授权该次或明确范围批次后发送；生成、下载、校验、质量分开 | 重新下载导致重生成；只切阶段就生成 |
| 查看成果 | 逐镜播放、看提示词、定位文件 | 展示真实产物、缺项与质量；“继续制作”直达缺项 | 显示不存在的完整成片 |

## 2. 图片生成／上传／替换共用确认层

入口保留对象上下文，例如“采用到：镜头 3 · 首帧”或“采用到：场景 · 夜间厨房”。左侧 contain 大图和多图缩略条；右侧显示来源、用途、文件信息、当前采用图小预览和影响范围。原型不承诺图片独立缩放；真实尺寸、解码和文件有效性由正式实现回读。普通界面不显示素材绝对路径、内部任务 ID 或原始记录。

状态动作：

| 状态 | 主动作 | 次要／更多 | 退出结果 |
| --- | --- | --- | --- |
| 无图片，提示词未就绪 | “生成提示词” | 上传图片、在豆包中调整 | 不生成图片 |
| 无图片，提示词已就绪 | “生成图片” | 上传图片、查看／编辑提示词 | 不自动采用后续返回图 |
| 上传文件校验中 | 禁用“采用这张”，说明正在检查 | 取消 | 原图片不变 |
| 文件无效 | “选择其他图片” | 取消、查看错误 | 不写入正式节点 |
| 单张／多张候选 | “采用这张” | 重新生成、上传替代、稍后处理 | 候选保留；当前采用图不变 |
| 替换已采用图 | “采用这张” | 当前图对照、暂不采用 | 底部明确说明替换；确认后旧图进历史，下游标记待复核 |
| 已采用 | “查看图片” | 更换、历史版本、在文件夹中定位 | 浏览不改变采用关系 |
| 批量已检查候选 | “采用已选的 N 张” | 清空选择、逐项查看 | 默认选择数 0，未检查图不得默认合格 |

人物／道具／场景卡和画布首尾帧节点都用这套交互。历史图再次采用也先预览用途。原型在本次浏览会话保留候选和被替换图，正式文件持久化待接线；批量检查图片并采用未在原型建模，上表保留为正式实现要求。

## 3. 豆包 Chat 辅助面板

1. 从对象“在豆包中调整”打开右侧面板，固定显示目标，例如“镜头 3 · 视频提示词”，保留同一关联会话。
2. 用户自由聊天时显示“正在调整此内容”；工作室暂停向该会话注入后续请求，不覆盖输入框草稿、不切会话。收起面板保留目标与聊天保护。
3. “选择回复”展开助手回复列表。每项显示顺序、简短预览、时间（可得时）和“查看全文”；单选，不默认最后一条。网页不能可靠定位具体消息时，明确让用户从可见回复列表选择，识别不确定则禁用应用并说明原因。
4. 选定具体回复后，主按钮“应用到当前创作”打开确认层，显示完整所选回复、目标、当前采用正文与新正文差异／并排查看。
5. 用户“确认采用”后，只保存这一目标。成功回填画布并恢复工作室后续可用操作。取消预览保留现有正文；目标已变化时提示“当前内容已更新，请重新核对这条回复”。
6. 如果回复只是解释或缺项，允许返回豆包继续讨论；需要结构整理时由豆包完成，不要求用户写 JSON。

当前自动请求仍为**工具自动发送**，源码证据为 `BrowserPanel.tsx` 的 `markSubmissionIntent` 与 `submitPromptWithNativeClick` 调用。外部 README／评审说明统一标明原型未连接平台；可点的回复选择与回填不代表已经读取真实豆包 DOM。若以后改成人工发送，应为“内容和附件已准备好，请在豆包中点击发送”，观察到发送后自动收取，不增加“我已发送”“开始监听”“确认收取”。

## 4. 异常恢复与成果状态

| 可见情况 | 用户文案 | 主恢复动作 | 边界 |
| --- | --- | --- | --- |
| 保存失败 | “剧本未保存，请重试保存” | “重新保存” | 保存成功前不发 Chat |
| 尚未发送，登录缺失 | “请先登录当前豆包账号” | “去登录” | 登录后核对原任务再继续 |
| 尚未发送，验证阻断 | “请在豆包中完成验证” | “去处理” | 不规避验证，不改写请求 |
| 已记录发送，平台结果不明 | “发送结果还未确认，请核对原会话” | “核对原会话” | 禁止重复发送 |
| 回复已读取、尚未保存 | “回复已收到，正在保存” | 无需用户点技术按钮 | 自动读取并保存；失败时“重新保存回复” |
| 归属不明确 | “这条回复还不能对应到当前内容” | “选择具体回复” | 不猜目标，不自动采用 |
| 回复格式缺项 | “这条回复还缺少可用内容” | “在豆包中调整” | 保留原回复；由豆包整理 |
| 旧回复迟到 | “较早的回复已保留，请核对后再用” | “查看候选” | 不覆盖新正文或手改正文 |
| 缺少确认首帧 | “这个镜头还缺少已确认的首帧” | “去确认首帧” | 正式视频引用只用已采用图 |
| 下载失败 | “视频已生成，下载未完成” | “重新下载” | 不重新生成、不追加 Chat 请求 |
| 文件损坏 | “文件未通过检查，请重新下载” | “重新下载” | 不标记人工质量失败 |
| 基础素材替换 | “参考图片已更新，请复核这个镜头” | “查看受影响内容” | 保留旧成果，不自动批量重做 |
| 生成失败且明确未受理 | “本次生成没有开始” | “核对后重新生成” | 先核对发送事实与授权范围 |

成果页逐项展示：请求／批次进度、图片生成、视频生成、下载、本地文件校验、与当前提示词对应、人工质量。一个维度完成不推导其他维度完成。示例：“视频已生成 · 下载完成 · 文件校验通过 · 人工质量待确认”。质量“合格／需调整”由用户决定；不从下载完成推定质量合格。

批量、任务恢复、下载、文件检查、备份及诊断在原型中是呈现状态；不执行平台调用或真实下载。上传后不能由“采用”推定文件哈希校验通过。真实回复来源、迟到消息保护、任务事实核对与产物校验仍是正式实现的验收要求。

## 5. 全产品按钮保留／合并／隐藏／取消清单

以下按正式源码现有入口映射到批准后的产品目标。此表保留完整能力范围；低频／批量／维护操作在原型中可仅展示位置与状态，未逐项接线不能视为交付。按钮同义文案以原型的上下文完整短语为准；“新增”仅满足已要求的交互。

| 当前入口或能力 | 处理 | 目标位置与文案 | 层级与条件 |
| --- | --- | --- | --- |
| 通用创作／萌宠短剧模式切换 | 取消前者、统一后者 | 直接进入“短剧创作” | 不保留切换控件 |
| 总览“进入通用创作”及 Studio 通用项目列表 | 取消可见入口 | 短剧项目／最近项目 | 保留业务数据，不在本轮删除数据 |
| 新建短剧项目 | 保留 | 总览、项目菜单“新建短剧项目” | 无项目时唯一主按钮 |
| 打开短剧目录／打开项目 | 合并 | 总览次按钮“打开项目” | 创作页项目菜单同一动作 |
| 继续当前短剧 | 保留 | 当前项目卡“继续创作” | 有项目时唯一主按钮 |
| 当前项目概览与元数据导出 | 移入更多 | 项目菜单“项目信息”／“导出记录” | 不占总览显眼工具栏 |
| 打开本短剧豆包账号／打开豆包 | 合并 | 全局“豆包 Chat”；对象入口传目标 | 不在项目头再放第二按钮 |
| 关联项目／执行账号／浏览账号多排 Tag | 合并显示 | 项目名下一行元信息；详情展开 | 关键错配就地警告 |
| 六阶段导航 | 保留 | 六个阶段名，单行紧凑横向导航 | 浏览不生成；不因访问后序自动画前序完成 |
| 多处“进入关键帧／查看视频／查看成果” | 合并 | 当前阶段底部一个下一步 | 同一阶段不另放快捷按钮行 |
| 画布全景按钮 | 合并 | 阶段 4/5 的同一完整画布 | 不再创建平行独立生产入口 |
| 高级编辑：故事、角色与镜头 | 移入更多 | 方案页“编辑方案” | 编辑保留；不与主流程抢权重 |
| 导出提示词与引用记录 | 合并 | 成果页／项目更多“导出提示词与素材清单” | 不生成媒体；一处权威入口 |
| 剧本输入方式 Segmented | 简化 | 默认原文；“从链接辅助提取”折叠 | 链接为次要入口 |
| 保存链接／复制手机豆包提示词 | 保留、隐藏默认 | 链接辅助区内 | 仅该区出现 |
| 仅保存剧本 | 保留次要 | 剧本文本域状态行“保存” | 主要操作为“分析剧本” |
| 分析剧本并生成方案／重新分析 | 合并 | “分析剧本”；已有方案时更多“重新分析” | 先保存，当前方案不自动覆盖 |
| 默认角色、风格、可选配角预设 | 保留、折叠 | 输入阶段“人物与画面偏好” | 展开后编辑，保存偏好 |
| 普通 Chat 免费可用确认 | 合并 | 制作设置内状态与必要核对 | 不每个阶段重复大 Checkbox；未知不能宣称可用 |
| 回复缺项时允许一次自动修订 | 移入更多 | 制作设置“回复修订” | 仅明确授权范围内，不绕过平台限制 |
| 补齐人物／道具／场景／资产清单 | 合并 | 方案／素材更多“补充素材清单” | 已有镜头与产物保留 |
| 审查当前方案与提示词 | 移入更多 | 方案“检查内容” | 非每卡显眼默认按钮 |
| 审查关注点 | 保留隐藏 | “检查内容”展开区 | 按需填写 |
| 采用此分镜方案 | 保留 | 候选方案“采用此方案” | 候选查看区唯一主按钮 |
| 确认方案并进入基础素材 | 保留语义 | 先“采用此方案”，再“确认方案并准备素材” | 确认不触发媒体 |
| 重新确认当前方案 | 合并 | 方案确认状态与重新确认入口 | 从素材高级区移走 |
| 增加镜头／添加必要配角 | 保留次要 | 方案编辑区 | 仅编辑时可见 |
| 上移／下移／删除镜头／删除人物 | 移入更多 | 对象菜单；删除二次确认 | 不做红色常驻按钮列 |
| 保存所有修改／保存正文／保存修改后的提示词 | 统一 | “保存修改” | 有草稿时唯一主动作；只写对应对象 |
| 放弃本次修改／撤销未保存 | 统一 | “放弃修改” | 次要；不得在无修改时占位 |
| 查看修改／保存并继续 | 保留按需 | 草稿提示条 | 点击定位对象；不覆盖其他草稿 |
| 生成缺失基础图／生成此基础图 | 合并 | 当前对象“生成图片” | 明确批次授权后才显示批次执行 |
| 上传已有图片 | 保留、统一 | “上传图片” | 各对象就地可见次按钮；必须待确认 |
| 查看后确认使用这张图片 | 改为确认层 | “查看并采用”→“采用这张” | 未采用图不进入正式节点 |
| 确认已逐张查看的 N 张图片 | 正式实现保留按需 | 选中工具栏“采用已选的 N 张” | 原型未建模；实现默认 0，已检查方可选 |
| 历史图片 Select | 改为预览入口 | 更多“历史图片” | 选择后预览用途再确认采用 |
| 重新生成图片（保留旧图） | 移入更多 | 更多“重新生成图片” | 先保留旧采用图；新图进候选 |
| 当前使用的基础图提示词 | 保留 | “查看／编辑提示词” | 默认简短预览；完整正文弹窗 |
| 豆包重新生成此素材／本项提示词 | 统一、次要 | 对象更多“重新生成提示词” | 与生成图片／视频明确分离 |
| 豆包生成编辑计划候选 | 保留、折叠 | 更换图片→“局部调整” | 指定基图、变化、保留、用途 |
| 采用此候选／采用这条回复／采用本次修订 | 统一 | 目标预览层“确认采用” | 先完整预览内容与对象 |
| 在豆包中调整 | 补齐一致入口 | 方案、素材提示词、每镜首尾帧／视频提示词 | 次按钮或更多；固定目标并暂停注入 |
| 自由 Chat 回复选择 | 新增必要交互 | Chat 面板“选择回复” | 不默认选最后一条 |
| 应用到当前创作 | 新增必要交互 | Chat 面板选中回复后 | 打开确认层，不能直接覆盖 |
| 全文／放大／完整编辑 | 合并 | 节点“全文” | 弹窗查看／编辑，返回原镜头 |
| 复制 | 保留、降级 | 全文工具栏图标＋说明 | 次要，不与生成同权重 |
| 审查本项正文／修订选中问题 | 保留、按需 | 对象更多“检查内容”；问题区“在豆包中修订” | 只影响该对象和明确选中问题 |
| 重新生成全部镜头提示词／全部基础提示词 | 保留、隐藏默认 | 制作设置→批量生成提示词 | 明示范围、候选方式和数量；不生成媒体 |

| 查看本次实际制作数量 | 合并 | 启动批次前预览“查看本次制作范围” | 范围／数量／缺项清楚 |
| 确认素材，继续镜头制作 | 文案收窄 | 预览确认“生成已就绪镜头” | 只有明确授权该批次才执行 |
| 单镜生成首帧／尾帧／视频 | 保留 | “生成图片”／“生成视频”→“开始生成此镜” | 根据对象和实际就绪状态显示 |
| 模型／模式／时长／降级选择 | 保留、上下文显示 | 视频节点“制作设置” | 真实入口支持什么显示什么；降级需明确同意 |
| 暂停制作 | 保留按需 | 正在制作的状态栏“暂停后续制作” | 已发送任务继续回读，不误称取消 |
| 适应、缩放、聚焦、镜头编号 | 保留 | 画布统一工具条／镜头定位条 | 阶段 4/5 都存在，键盘可用 |
| 准备基础素材／查看方案重复工具栏 | 合并 | 左侧故事与素材节点、阶段导航 | 不重复放在画布主操作栏 |
| 打开对应豆包原会话／核对当前原制作会话 | 统一 | 异常处“核对原会话” | 有不确定提交记录时主要恢复动作 |
| 收取回复／确认收取／开始监听 | 合并为自动技术动作 | 自动读取保存；失败时“重新保存回复” | 不要求用户重复确认已发送 |
| 结束等待／保留历史候选 | 保留、更多 | 任务详情“结束本次等待” | 解释原平台任务仍可能继续；迟到候选不覆盖 |
| 已发送记录下的重新执行 | 限制 | “核对原会话” | 不能显示通用重试自动重发 |
| 重新下载原产物 | 保留、简化 | 下载失败处“重新下载” | 与重新生成分开 |

| 暂停／继续全局调度 | 保留、降级 | 任务中心更多；暂停状态显著可读 | 不影响自由 Chat 草稿 |
| 编辑提示词并重跑 | 移回对象 | “回到创作中修改” | 短剧任务保护对象关联；不绕过候选采用 |

| 通用新作品、任务模板、任意模式创建 | 取消创作入口 | 短剧相关任务由创作对象组织 | 不删历史数据或短剧任务能力 |

| 账号添加／切换／登录验证 | 保留 | 账号与浏览器页面 | 不复用其他账号会话；忙碌时说明保护 |
| 置顶／取消置顶、冷却、暂停调度、编辑 | 保留、更多 | 每账号菜单 | 置顶事实不被可用性排序改写 |

| 清除登录并刷新／删除账号 | 保留、危险区 | 账号菜单独立分隔 | 确认对象、影响，不默认清理 |
| 全宽浏览器／收起浏览器 | 保留、图标 | Chat／浏览器标题行 | 不切会话、不销毁后台账号 |

| 检查完整性、备份、恢复 | 保留、分组 | 设置与诊断“数据与备份” | 恢复为危险动作，明确备份范围 |
| 日志、诊断包、页面兼容性、适配规则导入／回退 | 保留、折叠 | 设置与诊断“诊断详情” | 不在普通创作节点显示 |
| 运行统计 | 降级 | 诊断详情 | 无装饰性统计卡 |
| 任务 ID、规则文件、完整请求、原始 JSON | 隐藏普通 UI | 诊断详情 | 普通文字不含内部机制；原回复正文仍可完整看 |
| Dola | 保留实验标识 | 账号添加与详情“Dola（实验，尚未完成验收）” | 不表述为生产可用 |

## 6. 文案冻结清单

导航：工作台总览／短剧创作／任务中心／素材与下载／账号与浏览器／设置与诊断。总览主标题：创作工作台。

阶段：输入剧本／确认方案／准备基础素材／制作关键帧／制作镜头视频／查看成果。

状态：尚未开始／正在处理／等待你操作／等待平台结果／已收到回复／待选择／待采用／已采用／已确认／需要复核／下载完成／文件校验通过／人工质量待确认／人工质量合格／失败。

提示示例：“图片已生成，请选择一张”“上传的图片将用于镜头 3 的首帧”“当前图片继续保留，采用新图片后再替换”“这个镜头还缺少已确认的首帧”“请选择你满意的具体回复”“将应用到镜头 3 的视频提示词”“视频已生成，下载未完成”。

不得作为用户文案：“复用原有执行器”“统一状态投影”“底层架构保持不变”“不让用户理解状态机”、规则版本、Skill 路径或内部 ID。设计样例标记在原型评审说明中，不混入正式产品标题。

## 7. 后续真实界面验收入口

批准后逐项验证：粘贴保存失败不发送；分析结果可见；方案确认不生图；生成与上传都先预览；多图只采用用户选中图；旧图保留直到替换确认；阶段 4/5 全画布与缩放仍在；Chat 多轮不注入／不改草稿；选择某条具体回复并预览唯一目标；迟到回复不覆盖；缺项可定位；提交不明不重复发送；重新下载不生成；逐镜成果维度分开。当前设计阶段不执行这些生产写入，也不声称验收完成。
