# Design

## Context

见 proposal。P1～P4 已有项目目录、Chat 结构解析、最终文本编译、TaskService hold 任务、运行绑定、原会话观察、下载与 FFmpeg 校验。当前缺少道具／地点实体、基础图确认状态和逐文件页面映射。

## Goals / Non-Goals

**Goals:** 增量扩展 project.json 与现有短剧业务页；采用不同剧本驱动集合；两次明确操作分别授权基础图和镜头制作。

**Non-Goals:** 不引入全局素材服务、其他模型、自动生成实验、P5、UI 重做或历史成果覆盖。

## Decisions

- 审阅反馈修正：正式 Chat 原文必须由消息 DOM 回读，经 TaskService 保存后交给项目收取；有提交意图但回读不确定只恢复观察，不以 Codex 校订文件或修改任务文件代替结果。
- 资产输入只投影该类可视字段，剧情作用、跨镜持有者动作和设计来源留作元数据。风格区分共同画面语言与人物、道具、场景补充，历史未归类风格保留供用户整理。
- 模型正文以该项 final 为唯一语义来源，阶段仅附加用途约束和参考用途，不再叠入旧 action／expression／propStates。优化输入按静态开始、静态终态、动作过程投影，身份采用已保存的规范文字，禁止无条件叠加默认物种与衣装。
- 编译保存结构化引用片段；真实页面绑定只解析引用片段，不能全局替换正文中的数字。上传证据包含文件摘要，菜单和节点验证素材目标及每次引用出现，专用槽独立校验。导出分别保存模型提示词、审阅元数据、计划引用与已有实际绑定／任务输入，不生成虚假证据。

- 计划增加 props/scenes 与镜头显式关系；逻辑资产和具体图片分离。项目材料条目保存分类型提示词、当前图片指针、精确图片摘要确认，assets 只追加版本。旧清单可读，不自动推断为已确认。
- 普通 Chat 提取结构，确定性编译三类基础提示词；未经剧本指定的设计显式标注 proposed。同地视角通过 parentSceneId 派生，派生生成依赖确认主图。
- 基础图生成复用 P4 的单步骤 hold／运行绑定／产物下载机制，单独运行阶段；生成收取只选择候选，必须用户接受。镜头批准、推进、草稿与发送前都校验确认摘要。
- 每镜首帧组合全部必要确认人物、道具、场景；尾帧只编辑选中首帧；视频按实际模式绑定。continue 保留实际末帧但合成首帧时重新使用确认身份与环境，避免漂移接力。
- 页面适配保存本次文件和上传预览的稳定对应，再解析真实编号；若入口提供 @ 菜单则选择对应项并回读引用节点，否则使用已核对的普通中文用途映射。任何歧义、缺图、超限或控件不稳定都在提交意图之前阻断。
- final 始终作为正文保存；逻辑占位在本次绑定中解析，数字引用错位阻断。保存编译快照及实际网页绑定回读，普通 Studio 路径保持原语义。

## Risks / Trade-offs

- [网页入口变化] → 结构化页面识别、逐项稳定回读和 fail-closed，离线不宣称真实平台适配已人工通过。
- [模型实体别名歧义] → 要求稳定 ID、别名与引用一致，用户清单可编辑；不本地猜测语义合并。
- [旧项目无道具／地点信息] → 显式补齐清单后才准许新的镜头写入，历史任务只读恢复保留。
- [替换已用于镜头的基础图] → 暂停后保留已有成果与旧绑定，新图重新确认，恢复时提示原制作快照变化，避免覆盖下游。

## Migration Plan

可选扩展字段保持旧文件可打开，用户显式确认清单才登记新材料；不批量改写用户数据。源码与本项目 OpenSpec 为唯一新增改动，不自动归档或发布。
