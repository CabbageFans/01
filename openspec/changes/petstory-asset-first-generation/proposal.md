# Proposal

## Why

现有短剧链只有角色与逐镜场景图，没有人物、道具、地点的通用资产清单及具体图片确认门禁。需要让不同剧本共用同一条基础素材先行链，实际上传与最终提示词可核对，避免把样例修稿当作工具改造。

## What Changes

- 动态提取人物、必要道具、可复用场景与镜头关系，默认主演配置保持可编辑，未指定设计明确待确认。
- 分别组织人物、道具、场景 Seedream 提示词；单独授权基础图生成，下载后等待用户检查接受，替换保留旧图并取消新图确认。
- 已确认剧本及所有需要的实际基础图片是镜头任务的前置条件，显式确认后再接原 P4。
- 每镜只上传所需确认素材，编译逻辑引用，逐文件核对页面素材与模式；原生槽位和普通引用分别处理，适配真实引用节点。
- 完善当前页面的素材清单、预览、接受、替换、重新生成及最终引用检查。
- 采用互不相关小型剧本离线验证可迁移性，不主动生成真实媒体，不开发 P5。
- 根据用户审阅关闭正式 Chat 回读、分类模板污染、阶段正文冲突、规范身份与引用绑定的通用缺口；增加产品内导出，禁止人工校订绕过正式收取。

## Capabilities

### New Capabilities

- `petstory-asset-first`: 项目内基础素材设计、生成、确认与镜头引用绑定。

### Modified Capabilities

无已归档主规格；复用 petstory-mvp、petstory-prompt-quality 与 studio-ui-refresh 的实现成果。本变更取代旧规划中针对具体故事、镜头数量的专项要求与一次授权所有生成的流程。

## Impact

现有 contracts、项目 JSON、PetStory Chat／Production 服务、IPC、store、短剧页面和网页上传／引用适配。沿用 TaskService、Repository、下载与提交保护，不新增模型、依赖、全局资产平台、编辑器、合成或发布流程。保留历史工作树、文件与任务，不自动提交、推送或归档。
