# Design

## Context

本轮继续普通 Chat 对话内化任务书，读取当前工作树及运行规则，不指定历史基线。旧版专用方言曾因能力记录缺失而未进入真实请求；全局禁止图片编号／@ 与目标方言冲突，编译器还会补用途和素材说明。以原始请求及原回复为验收依据，不能用编译后正文替代。

见 proposal。当前原项目 v162 有五个稳定镜头、三名角色与历史关键帧，但没有道具、地点及基础素材清单。旧 analysis 同故事仅允许一次且直接覆盖方案；正文候选只有 optimized 字符串。当前任务书覆盖旧时间盒及禁止真实 Chat 的历史条款。

## Goals / Non-Goals

**Goals:** 规则与事实实际进入普通 Chat，当前项目可重新分析、补资产、生成完整正文、审查和局部修订，保护用户编辑与已有媒体。

**Non-Goals:** 不移植上游目录系统、供应商执行、付费 API、整片生产或通用 Agent 平台；不改账号会话生命周期和画布布局。

## Decisions

- 分阶段任务分别交代目标、实际规则、确认事实、共同状态、目标素材标签与返回契约；Chat 看图编号和最终媒体标签分开。未知模型如实标识，实际选定模型才加载对应方言。
- Seedance 的目标标签和方言格式由 Chat 在正文中写出。程序只将已存在引用按稳定身份解析、重编号并交给原生节点／槽位；不补写目的、动作、表情、编辑保持项或固定前后缀。
- 校验只陈述具体结构、引用或方言缺项，携带原请求和原回复交回 Chat 一次完整修订；无字数或关键词评分。用户手改 final 保留，新候选及无效原因可追溯。

- 用可随 tsc/Vite 打包的 JSON 保存按阶段适配的规则正文和来源；主进程按当前项目构造真实请求。开发环境与构建均不依赖临时上游 checkout 或工作目录。
- 复用 prepare→hold TaskService→绑定原运行→唯一最终助手正文→collect；新业务入口生成 requestId、精确 targetIds、规则版本与源文件记录。原文先保存，解析失败保留证据且不拿旧 final 填空。
- analysis 在已有 plan 时保存新候选；资产补齐按原 shotId 更新关系与缺失来源字段，保持原五镜主要动作、起终、参数和媒体。原剧本文字、当前采用故事、保存角色资料和图片分层注入；历史 prompt 只作为被修订对象。
- shot 与 plan 仅新增可选的理解、来源、导演、空间、表演与声音数据；候选及审查结果保存在既有 jobs，不引入第二状态源。读写验证须保留这些字段。
- prompt 保存 sourceJobId/candidateJobId。输入正文、故事、事实或目标被改动时新结果标记过期，仅保留候选；显式采用通过 job 读取原结果，revision 校验。手改 final 不自动替换；未手改且上下文未变时自动采用本次正文。
- 基础图、首帧、尾帧及视频按适用资产和真实关键帧分别传附件；Chat编号与媒体编号独立，生成任务仍经原逻辑引用编译及原生槽位核对。缺图仅产计划稿，媒体门禁保持。
- review 输出带实体、证据、影响、目标和严重程度的问题，revise 只允许相关目标一次，保存新候选，不替换无关条目。不以风格建议锁死项目，不无限自动重写。
- 画布在既有故事卡和折叠区补入口；已有单项和批量正文按钮切至新业务服务。页面装载与缩放不调用模型。真实验证可短时用诊断接口调用同一服务；原任务启动仍优先正式 local-control。

## Risks / Trade-offs

- [模型输出长或格式错误] → 分阶段／单项请求、完整原文保存、精确 ID 校验与有限格式纠正，不截断规则或用摘要兜底。
- [原项目缺少确认图片或当前模式能力未知] → 允许文字计划稿，明确未经看图／未绑定／未就绪；用户操作媒体验收。
- [原会话受理或回读不确定] → 保留任务只读恢复，不新发替代请求。
- [旧身份或台词曾被错误 prompt 污染] → 只从当前故事、保存资料及实际上传图获取事实，历史正文不能反向成为来源。

## Migration Plan

新增字段可选，旧项目原样可开。通过原服务补齐和采用，不离线改真实项目 JSON。实施 M1～M5，逐项记录代码、离线与真实文字状态；以原五镜头验证并启动普通应用，不提交、推送或归档。
