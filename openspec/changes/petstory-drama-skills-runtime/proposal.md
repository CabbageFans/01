# Proposal

## Why

当前画布已有普通 Chat、素材确认、逐镜生产及 drama-skills 实质规则。本轮真实请求核查发现，旧视频请求未取得目标模型方言，旧约束禁止了目标引用，尾帧任务缺少明确编辑基准，编译器又补写了创作说明。需要把现有规则落实到分任务的自足对话，让豆包原回复自身包含完整正文及对应表达，再无损保存、采用和绑定。

## What Changes

- 将固定提交的剧本、资产、图片、分镜、视频、审查方法适配为分阶段随应用构建的规则资源，保留来源和 MIT 许可。
- 服务端从当前故事、资料和真实附件构造自足请求，沿既有 TaskService 普通 Chat 单次提交与正式回读链保存完整正文。
- 分开 Chat 分析附件与目标生成标签，提供可信首尾文字及前镜持续状态；移除编译器的创作补写，仅映射已有引用。结构化事实使用代码围栏保护原文转义，回读仍核验完整内容。
- 已有方案支持重新分析与动态分镜候选、保持原镜头的资产及关系补齐；首帧、尾帧、视频和基础素材分别加载规则。
- 内容审查提供具体证据及定点修订；候选记录来源、过期状态与显式采用入口，保护手改 final，统一画布、导出和正式任务输入。
- 以原五镜头执行真实文字验证并保存证据；媒体仍由用户确认素材后操作验收。

## Capabilities

### New Capabilities

- `petstory-drama-runtime`: C01～C14 的规则宿主、普通 Chat 创作、审查、候选及采用链。

### Modified Capabilities

无已归档主规格；复用已有 change，不改写其历史验收或 P5 状态。

## Impact

涉及规则 JSON、PetStory 契约／项目／Chat／IPC、既有画布与 store、必要行为测试及说明。保留未提交工作树，复用既有浏览器、账号锁、上传、引用、下载与媒体门禁。不引入模型 API、第二状态系统、工具链升级、整片合成或发布；不自动提交、推送或归档。
