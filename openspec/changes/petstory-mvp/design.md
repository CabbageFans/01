# Design

## Context

动机见 `proposal.md`，业务边界见 `specs/petstory/spec.md`。以下来自本工作树源码，而非历史上游描述；已有 Mac 改动保持不动。

按用户本轮确认，v1.2 中本地原视频备用和未限定单镜头时长的表述在本 change 内被覆盖：抖音链接仅作来源记录；工具提供手机豆包提示词，用户粘贴故事后桌面 Chat 制作方案，每镜头 5～10 秒（含边界）。不修改旧应用的通用视频能力。

## Goals / Non-Goals

**Goals:** 一个业务状态对象、一个项目清单、少量原执行链分支即可走通；每一步有稳定任务和本地资产绑定，失败后能够确定下一步是否允许发送。

**Non-Goals:** 不更换现有账号／Session／调度架构，不迁移 Mac 或数据库，不建设通用工作流引擎、适配器平台或额外服务；完整范围沿用 proposal，不扩展其他 AI、收费接口和发行工作。

## Decisions

### 1. 手机豆包提取、故事回填后继续

来源仅接受抖音分享文本／链接，生成可复制到手机豆包的简短中文提示词，只要求按先后顺序讲清谁做了什么、接着发生什么及结尾，保留关键动作和对白；看不清或无法读取就直说，不猜、不编，不指定五段格式或人物动机分析。用户自行在手机端发送并核对，将完整原文粘贴回工具。普通文本即可，不要求 JSON；复制和保存均不创建任务或发送模型请求。

桌面端停止通过链接读取视频，只将来源 URL 作溯源记录，依据已保存原文完成故事改编、动态角色／镜头和首次提示词优化。缺少原文时 UI 与主进程均阻断创建／启动。模型通过 storyUsable 表明所提供故事是否充分，contentBasis 仅整理粘贴文本；不得声称桌面看过视频。故事不足时保留原文与角色设置，允许补充。

project.json 新增可选 mobileStory:{id,text,importedAt}，任务绑定 sourceStoryId。新原文生成新 ID，同文保存幂等；只处理同一故事版本的回复。未取得方案时可更正故事；已有方案／媒体草稿时更换来源需新建项目，保留用户最终提示词。旧项目缺此字段仍可打开，旧直读任务保持身份与原文但不启动／重试／格式纠正，手机故事保存后可创建新流程任务。已提交结果仍只读核对，不重复发送。

不建立本地原视频选择器、下载、复制／导入 IPC 或来源抽帧。角色参考图、生成视频实际末帧提取和本地成片用途保持。手机端解析能力和内容准确性仍由用户真实验收；不根据用户提供的平台说明宣称内部接口机制已核实。

### 2. 一个 `project.json`，先保存真实功能再逐步扩字段

关联 `studioProjectId` 和用户选定的一个 `accountId`，使用用户打开／创建的普通目录：

```text
project.json
# 链接、手机故事原文及导入时间保存在 project.json；无来源视频目录
characters/             # 用户主演参考与必要配角参考
shots/<shotId>/         # 选中关键帧、视频、实际末帧及保留的旧素材
exports/                # 合成 MP4
```

最小清单增加 `schemaVersion`、抖音链接与手机故事原文、`sourceSummary`、`adaptedStory`、动态 `characters[]/shots[]`、分析原文及 taskId/runId、当前步骤和导出记录。角色包含 ID、main/supporting、剧情作用、外观和参考资产。镜头包含顺序、角色引用、场景、动作、5～10 秒内的 `durationSeconds`、起止状态、cut/continue、previousShotId、请求／实际模式、提示词版本和资产绑定。

资产记录相对路径、kind、taskId/runId、artifactId 或 URL 归属、downloadJobId、尺寸／时长与选择标识；实际末帧另记源视频选择标识及提取时间点。路径、任务 ID、最终模式和 ffprobe 参数由程序生成，不接收模型任意路径。`plannedEndImage` 与 `actualEndFrame` 使用不同字段，避免错接。

清单与文件操作只经主进程校验后的业务 IPC：同目录临时文件加 rename 原子保存，拒绝越界路径／符号链接逃逸与未知版本，不损坏上一份有效文件。Studio `tasks.json` 仍只能由 TaskService/Repository 写入。对同一项目操作串行化；用步骤的持久化 taskId 和原任务回读去重，不先造通用事务／DAG 框架。

### 3. 复用 Chat 判定，单独保留可解析正文

扩展现有消息探针，在相同的本次消息节点内提取保留换行、段落和代码块的原文；现有规范化字段继续用于发布匹配与稳定判定。普通 Chat 复用附件读取／上传就绪规则，补上当前非 Chat 条件遗漏的路径，不读取整页正文。

PetStory 的稳定最终原文先经受限业务 IPC 按 projectId/taskId/runId 保存到清单，再完成分析阶段；若保存失败，不重发已受理请求。重开时沿用原任务及原会话只读补取正文。媒体 `outputs` 与下载产物仍保持原语义，正文不假装可下载 URL。

结构校验接受可变数组但要求两个固定主演、至少一个有效镜头、唯一 ID、合法引用、5≤durationSeconds≤10 的有限数值和有效模式；兼容 JSON 外层代码围栏，不改变字符串内部空白。首次故事／分镜提示明确每镜头 5～10 秒，不固定镜头数或总长。错误最多以独立绑定任务进行一次格式修正，仍错则暂停。规划阶段展示故事及实际数量，制作确认只做一次；编辑镜头、保存和重开复用同一时长／引用检查，4 秒、11 秒、缺失及非有限值明确报错，不静默钳制。

### 4. 两类规则直接进入最终任务输入

增加两份本地文本规则，通过现有 Vite `?raw` 读取。仅改编需求所列两个 MIT 项目的相关规则，实施时固定采用 commit、保留许可和规则版本，不导入其模型调用脚本、英文质量承诺或 Python 运行时。

用小型确定性函数检查角色映射、上传顺序、缺图／缺尾帧、空文本和模式；自然语言优化交给同一豆包 Chat，可与首次故事／分镜请求合并。分别保存 original/optimized/final 和用户编辑状态，重新优化只针对用户选中项。创建生成任务时只取 final，提交前使用原输入验证回读；用测试截获实际任务／运行输入证明没有提交旧文案。

### 5. 能力确认与每次提交回读分开

只在已登录且用户可见的普通创作入口做一次有界、无提交的能力检查，记录检查时间、入口可见性、首／尾槽、可选时长／比例和免费状态，PetStory 只使用免费选项与 5～10 秒区间的交集；不上传、不点发送，不请求隐藏接口。无窗口、未登录或短时不确定就记录待用户确认，不能为检查启动登录流程或反复探查；当前 0/1 状态跨会话保留。

`requestedMode` 保留用户意图；程序按检查结果和本次控件回读决定 `resolvedMode`（未核实先保持未解析）及原因。原生模式有两个明确输入时才实现角色化槽位绑定；尚未适配标“实现缺口”。明确不存在、收费或未知时，只用已批准备选；严格首尾帧请求暂停。每次实际提交前仍必须重新核对输入与免费条件，这属于安全回读，不重复做能力探索。

时长接线从校验后的 `shots[].durationSeconds` 映射到该镜头 `Task.videoConfig.duration`，写入原 `runtime.input.videoConfig` 快照，并经现有 `configureVideoOptions`／提交前回读确认与计划相等。5 秒、10 秒均可用但仍需真实免费选项；若区间内没有可用选项、当前值不可选，或页面回读为其他值（即使也在区间内），在发送前暂停。旧类型允许的 4s／11s～15s 不能漏入 PetStory，不在模型解析、列表编辑或任务创建时默认改成 5s／10s。

### 6. 业务编排只推进一个步骤

在一个 PetStory store 中保留可运行／暂停／待确认与当前步骤；角色参考 → 镜头首帧／可选尾帧 → 视频 → 下载依次推进。创建用 `window.electronAPI.tasks.add([finalPrompt], ...)` 的单项数组，避免 `useTaskStore.addTasks` 的 `%%%%%%%%%%` 文本拆分；任务先 hold，经已有 assign、arm/start 与队列执行，不直接操作 Webview 发送。

taskId 必须在授权执行前写入清单并回读；同一步双击合并，只给当前步骤授权。若创建返回不确定或清单绑定失败，停止且不自动重新创建，保留原 hold 任务待核对。恢复先查原任务：done 则关联／下载，已受理则观察原会话，不确定则暂停，确认未提交才允许正常继续；不能把 resume 变成重新 retry。任务完成、文件下载并校验、清单保存成功才推进下一个步骤。下载通过现有 `downloadOutputs`，从 `listDownloads` 按 jobId/taskId/产物定位路径；失败沿原 URL 下载，绝不调用生成重试。

免费权益在 PetStory 每个可能写平台的步骤前核实，未知即暂停，不能把本地预计单位、可点击按钮或“allowed”当免费证据；记录用户可核实的当前入口状态，不要求精确余额。既有素材仍可下载、预览和合成。不更换账号规避额度，不改变现有 Session、前台交互租约或预热策略。

### 7. 连续接力与局部重做用显式引用

`cut` 不引用上一帧。`continue` 仅引用上一选中、已下载有效视频；FFmpeg 从其有效区间末端提取最后可解码非黑帧，记录源选择标识，失败暂停，不借计划尾图兜底。首尾模式仅给需要精确终态的镜头制作尾图。

动作变更只建有关视频任务；关键帧变更再重做引用它的视频。新素材写新文件，成功后再替换选中指针。扫描 shots 数组中明确引用旧选择的连续段并标记过时；用户可保留旧片改 cut，或更新绑定并重做这一段。仅这类线性关联向后处理，不扩成通用依赖图或自动整片返工；成功后重新合成。

### 8. FFmpeg 合成与一个渐进接通的页面

主进程使用已安装 FFmpeg/ffprobe，以参数数组、无 shell 的子进程执行，支持取消和临时文件收尾。下载后由 ffprobe 记录各选中镜头实际时长，超出 5～10 秒则标异常、阻止后续使用及合成并保留原任务／素材，不自动重发或用拉伸、循环、静默裁剪修正。全部镜头有效后统一编码、帧率与 9:16 画布，优先 scale+pad；混合有声／无声片段时仅在缺音轨处补静音以保持原音轨和片段时序，不补造缺失画面。按实际顺序 concat，总长随镜头数和各段时长累加，验证输出可解码和实际时长后原子替换成片指针，失败保留旧片。

业务页在来源、故事、优化、制作、合成各阶段同步接通，P6 仅整合。新增页签使用现有 Ant Design 深色主题，故事与镜头简单列表编辑，提示词和模式详情折叠。切换页签不得卸载 `BrowserPanel` 或销毁账号 Webview。现有预览组件主要面向远程产物，因此本地播放需受限项目媒体协议：只按已打开项目和登记资产提供本地媒体并支持播放所需读取，不开放 HTTP 监听或任意磁盘访问；Finder 用受限 `shell.showItemInFolder` IPC。

新增代码按实际功能集中在 `src/components/PetStoryPanel.tsx`、`src/store/usePetStoryStore.ts`、`main/ipc/petstory.ts` 及两份规则文件；较独立的媒体／校验函数确有需要再拆。共享纯类型补入 contracts 并导出，preload/ElectronAPI、main IPC 注册生命周期同步接线。不预建大量空模块，不修改运行时 AI 引擎或整个 App 布局。

## Risks / Trade-offs

- [手机故事可能不足或不准确] → 保留用户回填原文、来源及版本；不足则提示补充，准确性由本人对照原视频核对，A1 未真实验收保持未勾选。网页链接直读已取消。
- [通用时长类型与平台结果超出业务范围] → PetStory 从 JSON、编辑／重开、任务创建到提交回读统一约束 5～10 秒，下载后再校验实际时长；超界即停，其他 Studio 任务的通用时长选项保持。
- [原生首尾帧及免费权益尚未确认] → 一次无提交检查、当前 pending；显式备选或暂停，平台限制与实现缺口分别记录，不把两参考图当原生模式。
- [JSON 格式、角色映射或内容质量不稳] → 本地结构检查＋最多一次格式修正；身份、故事与连贯效果由用户看实际视频验收，不许诺一次成功。
- [网页加载慢／用户介入导致中断] → 保留已有原会话、单次提交与恢复保护；等待计入总预算，不重复做已完成 Mac 修复。
- [跨任务文件两次写入之间退出] → 执行前先持久化绑定、各阶段幂等回读、只授权当前步骤；写入或归属不确定即停，不靠重复生成修复。
- [原时间预算（用户已取消本轮继续测试的截止限制）] → 原起点 `2026-10-24T09:52:13+08:00`、截止 `15:52:13+08:00` 不变，P0 20 分钟＋P1～P7 340 分钟；超时占余量，14:52:13 后不加功能，15:52:13 停止扩展并交接是原计划；用户随后明确“继续完成测试，不用管时间了”，本轮仅 P1～P3 修复及验证不限时，原开始记录不变，保留所有未完成项。

## Migration Plan

无数据库或账号迁移。按阶段为用户选择的目录写入带版本的清单；既有 Studio 项目、任务与 Session 不变。回退时停止 PetStory 编排并保留项目和素材，不删除历史任务；重新打开仅展示并校验来源、时长与状态，用户显式继续后才允许授权执行。发现本地原视频来源或越界时长的 PetStory 清单时报告不符合当前范围，不自动转成有效抖音来源、改时长或覆盖旧素材。

实施后做相关离线行为测试和现有 `pnpm run validate`，通过也不勾选 A1～A8。真实验收与原生首尾帧实测另记，交付只能按实际程度标“部分完成／实现完成待真实验收／完整 MVP 通过”。当前 P1～P3 已实施；来源流程按最新用户指令修订，真实验收另见进度记录。
