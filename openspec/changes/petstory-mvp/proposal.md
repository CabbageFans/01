# Proposal

## Why

当前 Studio 已有账号、单次提交、生成观察和下载链，但参考视频到短剧成片仍需人工分析与搬运素材。按 `docs/PRODUCT_REQUIREMENTS.md` PetStory Studio v1.2，在现有 Mac 底座增加一条可保存、可继续的萌宠短剧制作流程。

本 change 按用户本轮确认覆盖 v1.2 的两处范围：每镜头时长为 5～10 秒（含边界），来源改为“抖音链接 → 手机豆包提示词 → 用户粘贴故事 → 桌面 Chat 制作方案”，停用网页自动直读，不实现本地原视频备用；其他需求与既有进度保持。

## What Changes

- “萌宠短剧”来源区接受抖音分享文本／链接，生成供用户复制到手机豆包的提取提示词；用户回填普通文本故事，保存原文后交给桌面 Chat 改编。取消网页自动获取剧情，旧直读任务只保留核对，不提供本地原视频入口（R01～R02）。
- 普通 Chat 处理分析附件与本次完整正文，生成相似故事、可变长度 `characters[]`、`shots[]`；固定噜噜、噜妹主演，必要时增加配角。镜头数量和成片总长按剧情决定，每镜头时长限定在 5～10 秒内且匹配实际免费选项（R02～R04、R06）。
- 内置两份 Seedream/Seedance 规则，保留原始、优化及用户编辑文本；最终文本实际用于生成（R11）。
- 按当前免费入口解析请求模式，明确首帧、原生首尾帧与普通参考图；区分切镜和连续段、计划尾帧和选中视频实际末帧（R05～R06）。
- 顺序接力角色图、关键帧、视频与下载；复用原任务身份、防重复提交和恢复；额度不足保存，受理不明不重发，下载失败不重新生成（R07～R08）。
- 用 `project.json` 与本地素材保存进度，FFmpeg 合成动态数量镜头，支持预览、局部重做及连续依赖过时提示（R09～R10）。

## Capabilities

### New Capabilities

- `petstory`：只定义本次短剧业务增量，覆盖 R01～R11，并映射用户验收 A1～A8。

### Modified Capabilities

无。当前没有已登记的 OpenSpec 主规格；不为旧应用补写整套规格。

## Impact

- 最小新增业务页与状态编排、项目文件／媒体 IPC；修改现有 `BrowserPanel`、`chatReadback`、`doubaoBridge`、共享契约和 preload 的必要接线，任务读写仍经 `TaskService`/Repository。
- 复用现有 Node/pnpm/Electron 和 `/opt/homebrew/bin/ffmpeg`、`ffprobe`；不重装依赖，不重做 Mac 迁移，不新增其他 AI、付费 API、Remotion、数据库、通用 DAG、MCP/HTTP 扩展、复杂编辑器或商业发行。
- 真实登录、免费权益、视频内容和成片效果由用户验收；原生首尾帧只有一次无提交页面检查预算，未登录或无法确认即记录待用户确认，不寻找隐藏接口。
- 总时间盒保持 `2026-10-24 09:52:13～15:52:13 +08:00`，含首 20 分钟准备与规划；超时占用剩余预算。执行清单以本 change 的 `tasks.md` 为准，需求原文中的 Spec Kit 流程不执行。
