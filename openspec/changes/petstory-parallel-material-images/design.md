## Context

参见 proposal.md 的动机。现有图片操作具有目标、基图摘要和任务身份，但当前制作及执行页按项目/账号单值保存。项目写盘已有串行事务和版本保护，发送已有意图落盘及原结果核对。

## Goals / Non-Goals

**Goals:** 不同基础素材的文字准备、图片生成和修改拥有独立持久化、执行页面、进度和恢复；同素材继续互斥。

**Non-Goals:** 不扩展视频并发，不轮换账号，不改变账号分区，不绕过验证码、不自动重发，不替代候选明确采用；真实平台可用并发数不在未验收时承诺。

## Decisions

- 项目增加按 operationId 保存的 imageProductions；通过操作作用域复用正式制作服务，保留旧 production 兼容。相比放松唯一指针，此法防止回调和恢复覆盖其他素材。
- 任务必须携带项目、materialId、imageOperationId 的明确绑定才具备图片并行资格。执行范围按账号/项目/素材划分；同素材始终互斥，普通任务仍排他。
- 每一操作运行使用独立任务页面，沿用原账号 partition，页面与 taskId/runId 绑定。保留账号常驻用户页面，独立观察/导航/清理，不复用其他账号页面。
- 保留全局输入/上传/发送短租约，受理后生成等待可重叠。并行槽设置保守上限，队列只限制执行数量，不阻止用户创建其他素材的操作。
- Store 活跃操作及观察授权按操作定位；所有项目短写入经队列取最新版本。后台等待不占写队列；上传/采用只保护真实相关输入。

## Risks / Trade-offs

- [同账号页面共享登录和平台额度] → 如实显示平台实际拒绝；登录及人机验证仍需用户处理，不宣称完全故障隔离。
- [迟到结果与跨操作回调] → 保留原 taskId/runId、基图校验与操作定位，恢复只收取原结果或补下载。
- [多页占用资源与可见控件要求] → 有限活动槽；保持执行宿主可渲染，结束后释放任务页面，账号页面继续常驻。
- [旧项目兼容] → 缺少新字段沿用原独占链；未绑定操作的普通任务不会获得并行资格。

## Migration Plan

新字段可选，读取旧项目不触发新请求。先完成契约与操作级持久化，再接调度/页面和素材状态。用离线并行、乱序完成、防重和恢复测试验证；真实豆包多页生成仍需用户实际验收。
