# Design

## Context

现有 buildDramaRequest、prepareRuntime、collect、adoptPromptCandidate 和 TaskService 已承接正式请求及来源；分析校验仍将 optimized 直接设 final。Store队列只驻内存；完整请求DOM回读过严；编译器缺合同提前放行，生产与导出存在项目级pending阻断。

## Goals / Non-Goals

把分析结果、正文草稿、专用候选与实际可提交区分，复用同一请求与采用服务。保持project.json、现有调度、账号租约和P4；不增加第二执行器、数据库、正文优化器或P5。

## Decisions

- 保留必有的firstFrame/video提示词容器，允许空字符串，增加draft状态；旧综合回复正文保留为计划，不赋专用来源。lastFrame按模式或既有计划可选。
- 阶段补齐复用串行队列，批次清单、进度及当前job持久化；重开恢复为暂停，显式继续才授权文字请求，不隐式创建媒体。
- 文字目标模型独立保存，规则选择在请求时完成；采用合同携带当前设计摘要与引用职责，编译、生产和导出共享资格函数。实际文件绑定不加入设计摘要，避免编号或计划解析无谓失效。
- 只读回读以原会话／运行／唯一轮次及本次目标为核心；DOM证明的显示格式规范化仅用于比较视图，原回复原样保存。结束等待为独立持久字段，不改任务的submittedAt或真实状态，迟到只存历史候选。
- 使用既有镜头、素材和前镜边界判断阻断范围；活动账号任务仍由调度及租约阻断，不建设通用DAG。
- 字幕约束有限同义识别，创作内容问题交回豆包；自动修订上限跟原请求绑定，用户新操作可新开一轮。
- 分析请求区分来源人物描述与本项目制作演员配置；有旧方案时仍独立提供当前配置及真实确认依据，映射、身份与完整方案由豆包落实，不由程序换名或换装。未确认的上次设计不能压过当前配置。
- 审查保存本次实际送审的逐目标final快照；后来的正文变化不能继续使用旧问题。格式修复只继承原快照，旧全局审查不补造历史。
- 采用动态新方案后，显式继续先检查保存批次的目标是否仍存在；旧未决任务先只读核对，其余过期队列经原阶段服务重取当前目标，不发送已删除对象。
- 制作演员配置可保存已有来源别名和主配角关系。分析请求从实际配置生成小型绑定快照，采用前核对明确的ID／别名归属和role；格式修复继承原快照，旧项目不补造对应关系。外观自然语言仍交内容审查，不按关键词或逐字比对改写。

- 分析收取、显式方案／资产采用共用身份保护：仅当前所选真实人物图、hash、角色归属及身份批准同时有效时保留已确认身份事实；旧同ID未确认设计不得覆盖本次豆包描述，真实选图绑定不升级为批准。
- 原生单次发送的稳定证据同时覆盖guest发送按钮与宿主映射点；租约异步核对后再次只读核对原位置、焦点与几何，变化即暂停，不改点补发。该防护不推定任何一次平台未受理的根因。

- 任务指派的Core结果data须由IPC显式映射为共享TaskResult.task；真实IPC到Store的回归验证成功回填，指派后仍hold，不启动队列或页面发送。失败保留原原因。

## Risks / Trade-offs

- DOM变化或歧义 → 保存事实、暂停猜测并提供原会话核对，不重发。
- 旧正文缺专用合同 → 保留可见计划，正常阶段补齐，不伪造元数据。
- 手改与新候选并存 → 保留final，明确下游使用旧采用版本，新候选须显式采用。
- 模型内容仍有实际问题 → 保留原回复与具体错误，至多一次自动修订，逐项报告未完成。

## Migration Plan

增量兼容schemaVersion=1，读取不改写用户正文或媒体，写入仍走项目原子服务。验证前本地备份真实项目及任务，不直接编辑运行数据；无提交、推送、发布或其他变更归档。
