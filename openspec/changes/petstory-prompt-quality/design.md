# Design

> 本轮已由 petstory-asset-first-generation 接续通用机制。下列历史样例生成与审查要求不再作为开发依据或验收条件，原产物保留。

## Context

见 proposal。基线 main/5d2cb9e，初始仅任务包未跟踪。六张关键帧已查看，无当前 Session 原视频。实际缺陷：optimizationPrompt 只传 shot 不传角色档案；applyOptimization 仅比较请求前 final，未检查 edited；Chat 按资产数组筛图，P4 按 characterIds；全文预检合并空白。

## Goals / Non-Goals

**Goals:** 复用原 JSON、TaskService、上传与单次发送，提供可审阅的最终提交正文。
**Non-Goals:** 不新增模型、生成实验、P5、UI 改版、迁移或自动发布。

## Decisions

- 轻量 JSON 保存默认身份／造型／共同风格，由项目可编辑字段覆盖；旧清单不迁移改写。新草稿带默认设定，旧项目通过显式优化使用。
- 主进程提供唯一编译与预览 IPC；renderer 的 Chat 上下文共享轻量 JSON 预设；前端有序素材投影与主进程实际清单以回归测试核对一致，编译只在主进程执行，不在纯类型 contracts 中放运行逻辑。
- final 是用户正文，compiled 快照仅添加当前素材用途／模式并解析明确的逻辑引用；旧自然语言错绑提示人工修正，不猜测改故事。P4 持久化 text、assetId、角色、用途、顺序和模式，UI 显示同一结果。
- 手改 final 只接收 optimized 候选，显式接受候选经原 savePlan 保存；保留并发版本检查，不重造编辑流程。
- PetStory 发送前独立严格回读，只允许 CRLF 换行规范化；通用 Studio 保持现有行为。

## Risks / Trade-offs

- [自然语言歧义无法完全确定] → 仅确定错误阻断，规则让 Chat 将情绪转可见表演；不按字数评分。
- [未来资产尚未生成] → 计划预览标注待就绪，实际创建必须以完整资产清单再次编译。
- [网页编辑器可能折叠段落] → fail-closed；离线不宣称网页及生成效果已验收。

## Migration Plan

可选字段向后兼容，不写用户现存项目，旧任务按已有输入继续只读恢复。不开启真实生成授权。
