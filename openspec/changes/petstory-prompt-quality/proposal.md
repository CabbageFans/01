# Proposal

> 本轮已由 petstory-asset-first-generation 接续通用机制。下列历史样例生成与审查要求不再作为开发依据或验收条件，原产物保留。

## Why

PetStory 单项优化未携带角色档案，预设缺少噜噜／噜妹身份知识，生成阶段引用与真实附件脱节；重优化还会覆盖请求前已手改的 final。本专项依据任务包关键帧补齐必要信息并确保用户看到的全文进入正式任务。

## What Changes

- 可编辑、分层的主演身份／项目造型／共同风格预设，仅作用于萌宠短剧，参考图与明确设定优先。
- Seedream 首帧、尾帧编辑和 Seedance 首帧、首尾、参考生成分别使用规则，优化输入带出场角色资料与镜头状态。
- 统一有序素材用途清单，按真实模式编译引用；保存可见提交快照，阻断确定错绑。
- 保护手改 final，重优化保存候选，由用户接受；严格全文回读后单次提交。
- 离线回归、四组前后对照、报告与应用启动，不发起平台生成。

## Capabilities

### New Capabilities

- `petstory-prompt-quality`: 专用角色、用途化提示词、实际引用绑定与可回读最终提交。

### Modified Capabilities

无；主规格尚未归档，旧 petstory-mvp 与 UI 变更任务状态保持。

## Impact

涉及 PetStory 契约／规则／Chat 请求与解析／项目保存／P4 任务组装／提示词详情和必要提交校验。复用 TaskService、现有上传／队列，不新增依赖、AI 或执行器，不涉及 P5、全站 UI、迁移、发布或 Git 操作。

## 追加授权范围

用户随后明确要求用新提示词生成全部图片，并确认当前原账号图片免费可用。本次仅执行5首帧及3计划尾帧的单次图片检查任务，复用原Studio／TaskService／下载链；不启动视频或P5，不重抽卡，不把用户原手改final改写为新稿。运行记录、真实原图及人工检查入口单独交付。最初无生成阶段的验证记录保持历史事实。
