# Proposal

## Why

当前萌宠短剧把故事、最终提示词、参考素材与产物分散在阶段和详情内，用户难以逐镜核对豆包回复、实际采用正文及生成结果。本轮按已确认截图，将这些现有能力组织为同一页分镜生产画布，停止提示词质量专项扩展。

## What Changes

- 在现有 React 萌宠短剧工作区实现浅色网格、白色节点和青绿色操作：左侧故事卡，右侧每镜一行，按“分镜及生图提示词 → 首帧／可选尾帧 → 视频提示词／运镜 → 镜头视频”对齐。
- 同页保留人物、道具、场景提示词与具体图片确认、上传、生成入口；支持完整文本查看、复制、编辑保存，平移、缩放、适应与镜头聚焦。
- 节点复用当前 project/store/TaskService、普通 Chat、素材上传、P4 生成和下载链；区分来源与候选，保留手改 final，异步新回复可见且可采用。
- 在唯一原五镜头项目，通过现有正常业务服务重新取得至少 13 项真实普通 Chat 正文并自动回填、保存和恢复；已有豆包媒体按真实归属展示，缺结果显示未生成。
- 分开提示词重生成、图片生成、视频生成和重新下载；导航和画布交互不触发提交、不卸载现有账号 Webview。
- 完成相关离线验证、实际 Electron 页面检查及截图，报告实际完成程度并启动应用。

## Capabilities

### New Capabilities

- `petstory-storyboard-canvas`: 同页逐镜生产画布、完整正文编辑与真实服务接线及本轮五镜头验收。

### Modified Capabilities

无已归档主规格；保留已有四个 change 的实现、状态和历史记录。本轮用户指令覆盖历史禁止真实 Chat／五镜头验收条款，不延续提示词优化任务。

## Impact

主要涉及 PetStory 页面、画布组件与样式，现有 store、IPC 和项目契约只在回填、保存、来源或绑定确有缺口时做最小修复。参考 ai_story 指定组件的布局和交互，在本工程独立实现；不引入其后台、API、品牌或媒体，不新增生成系统、P5、配音、字幕、发布或依赖迁移。保留当前工作树，不提交、推送或归档其他变更。
