# Proposal

## Why

用户已有剧本时仍需猜测账号、方案采用、素材确认和镜头生成之间的下一步；禁用与恢复入口分散在隐藏区域。需要让现有能力组成可在真实 Electron 窗口操作的完整接力，并准确呈现尚未完成的成果。

## What Changes

- 将现有数据派生为输入剧本、确认方案、基础素材、关键帧、镜头视频、查看成果六阶段；保留原画布与高级编辑能力。
- 新建入口直接选择账号和关联项目，默认直接输入剧本；可靠保存后才由明确操作触发普通 Chat，完成后交接方案采用与制作依据确认。
- 每阶段推荐一个范围与数量明确的动作，当前页提供前置处理、任务恢复、具体对象的草稿保存／定位／放弃和候选采用。
- 增加复用现有主进程校验的只读生成资格查询，按实际目标、文件和确认事实展示进度；提供安全的成果文件定位。
- 用用户原故事正常新建及打开原五镜头项目，逐步记录真实控件、反馈和窗口截图；分别报告离线、真实 Chat、真实媒体边界。

## Capabilities

### New Capabilities

- `petstory-user-journey`: 六阶段用户接力、就地阻断处理、真实成果与可见流程验收。

### Modified Capabilities

无已归档主规范；其他在途变更及未完成验收保持原状。

## Impact

修改现有 PetStory 页面、素材／画布／运行时组件、轻量 UI 状态投影、store、主进程只读 IPC 与共享契约及相关测试。继续使用 drama-skills、豆包普通 Chat、TaskService、现有媒体链及 project.json；不引入新模型 API、第二工作流引擎或 P5，不提交、推送、发布或归档其他变更。

## 2026-10-29 获批产品化增量

用户已明确批准 `docs/ui-design-review/2026-10-29/full-product-design` 最终设计，按其规范和原型统一正式短剧工作室。接续本变更；studio-ui-refresh、storyboard-canvas、drama-skills 作为已有实现依赖，不另建系统、不抹掉历史验收边界。

- 统一命名、浅色中性与深青绿；取消通用创作可见入口，保留短剧所需任务／下载／账号／设置诊断能力。
- 六阶段中关键帧和视频始终保留完整 ai_story 画布及其视角、横向节点对应。
- 全部基础图和首尾帧的下载、上传先登记候选；预览并明确采用后才改变正式引用，旧采用图保留历史，下游只标待复核。
- 增加当前对象关联自由 Chat、自动任务保护、具体助手回复选择与完整应用预览；明确采用后只更新该对象，并校验版本及来源。
- 当前普通 Chat 仍按实际自动发送链；人工发送只有完成真实能力后才显示。创作正文继续由豆包真实普通 Chat 提供，程序不补写。
- 完成行为测试、完整门禁和真实 Electron 用户流程／双尺寸验收，分别报告文字、媒体、下载、文件校验与人工质量；用户确认与平台阻断不得伪造通过。

## 2026-10-29 流程与 UI 收敛增量

接续用户最新指定截图修复，不生成新设计。最新产品规则将历史“采用后再确认”合并为方案卡的“确认并采用方案”；明确批准记录优先于设计目录仍标“待批准”的历史文字和旧深色规范。分析与其修订按请求族投影为一个审阅结果，来源／完整请求默认留在诊断；未确认方案不能呈现可执行素材控制。补齐自由 Chat 具体图片回复的收取、预览和明确采用，沿用原项目、账号会话、下载与图片服务。新方案采用只复核实际影响，保护已有正文、图片和历史。完整实机创作仍以用户明确决定及实际生成事实为准。
