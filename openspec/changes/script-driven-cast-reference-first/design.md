# Design

## Context

见 proposal.md。当前 profile、Chat facts、素材同步与身份确认都含外观文字。采用服务已提供统一保存边界，生产已有逐镜素材摘要及图片采用记录，复用这些结构。

## Goals / Non-Goals

目标是让当前图片成为视觉依据，保留剧本角色稳定 ID、关系、镜头、逐字台词。保留既有执行器、项目文件与普通 Chat，不新增通用依赖引擎或界面向导。

## Decisions

- 采用服务在一次项目保存中记录视觉图来源与旧基础提示词失效关系，保留正文和原任务。仅上传候选不切换依据；不伪造文字来源。
- 图片就绪检查采用关系、角色归属和可读文件，不比较旧 description。人物图生成仍要求真实专用提示词来源。
- 分阶段投影角色事实：基础图可使用明确设计；关键帧与视频只使用角色 ID、制作标签、关系和当前图片。来源剧本和原回复单列追溯属性，不能作为锁定造型。
- 制作标签与 speakerId、图片引用合同共用映射；不通过文字颜色黑名单修改动作或对白。
- 素材与镜头摘要只纳入当前有效依据，换图标记实际依赖的旧帧与旧正文。正常生成时由普通 Chat 修订为候选；历史媒体及无关镜头不变。
- 旧默认只按可证明的原样继承识别；不按名字删除用户设定，不在打开项目时请求平台。

## Risks / Trade-offs

- 旧正文可能包含外观且不能机械修剪 → 保留原文、沿当前生成／修改入口交由 Chat 创作修订。
- 平台登录或提交不确定阻断真实验证 → 保留原任务，完成独立代码和检查，逐项记录缺口。
- 首尾图更换与旧规则重复复核存在冲突 → 只处理真实角色图依赖变化，常规提示词／参数变化不撤销已采用图。

## Migration Plan

兼容读取旧字段，显式采用或创作时写入最少来源关系。启动和重开不改写故事、原回复、媒体或已发送快照。无需批量迁移。
